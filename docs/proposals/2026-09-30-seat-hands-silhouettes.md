## 2. 現況事實（雲端讀碼所得，接手請再核對）

- 籌碼／令牌／信物在 `js/table-props.js`：籌碼 `FLY_MS` 0.42 秒、同席錢間隔 0.035 秒；令牌 `SLAM_MS` 0.30、`RISE` 0.34、`BOUNCE` 0.055；揭盅收錢 0.22 秒延遲＋0.42 秒返回。
- 四席錨點 `PROPS.SEAT`（世界 x／z）：橫式 南 (0,1.22)、北 (0,−1.92)、西 (−1.38,0.98)、東 (1.36,1.06)；直式另一組。**南席已被收進視野內**（原 `SEAT_POS` 半徑 2.6 在視野外），所以玩家自己的手**可以**出現在畫面，不必只從畫面下緣硬伸進來。
- 每件道具的凍結預算：**≤300 三角形**（凍結檔 U3）。寫實手必然超過，**需要使用者裁定新預算**（§8 D1）。
- 道具層**不在 `tray.hitTest` 的命中代理裡**（凍結檔 U2）；手也必須維持這點，不能擋住拍品的點選。
- 桌面 draw call 基準約 82～83（v0.59.2 鑑賞頁卷的 #8）。效能 gate 是 **Chromium 相對速度比**，不是 Safari fps。
- GLB 管線已有：`js/creature-figures.js` 用 `SkeletonUtils.clone` 複製骨架、`js/skeleton-share.js` 讓同一份網格共用一副骨架（每幀骨骼貼圖上傳 51→5，v0.57.14）。**手應走同一條管線**，不另起爐灶。
- 美術規範（`docs/design/ART_BIBLE.md`）：無貼圖、只用**幾何＋頂點色**；陰影全程關閉；**不可愛**；動手前要有 **2～3 張真實參照＋3～5 條一眼特徵**（§0.5）；「純色無光照 billboard 剪影」曾盲讀 0/3、被判像剪貼畫而退場（§6 特效段）——**人影不能是平面貼片**。

## 3. 最佳解：一份共用的寫實手 GLB＋四席複製

### 3.1 為什麼這樣做

- 一份模型、四席複製，沿用既有骨架共用機制，draw call 只增加「席數」（≤4），不隨角色數增加。
- 用 anyCreature 做（與其他 27 件資產同管線、同頂點色語言、已能輸出帶骨架的 GLB）；**Modly 不當執行期資產來源**——AI 生成的網格通常無骨架、面數高、要手工減面補骨，風險大。Modly 可拿來產**參照圖／姿勢概念**，但最後入庫的仍是 anyCreature 的低面數帶骨 GLB。（以上對 Modly 的判斷是依一般 AI 生成 3D 的常見情況推測，接手者請用實際輸出驗證，不對就改判。）

### 3.2 模型規格（提案）

| 項目 | 提案 | 備註 |
|---|---|---|
| 構成 | 前臂＋袖口＋手掌＋五指（拇指 2 節、其餘 3 節） | 寫實指節比例，見 §3.3 |
| 單隻面數 | **≤2,500 三角形**（使用者 D1 裁定；手約 2,000＋前臂與袖口約 500 為建議分配） | 四席共 ≤10,000，**高於銅錢池上限 8,192**；A1 相對效能 gate 與手機 fps 風險要重量 |
| 骨架 | 腕、掌、每指 2～3 節，約 20～24 根骨 | 所有手共用同一副骨架資料 |
| 上色 | 頂點色：膚色＋指節／指甲／掌紋的暗部；袖口單獨一個色帶 | 一色定調：**角色主色只落在袖口一個部位** |
| 左右手 | 只做右手；左側席位用鏡像（負縮放會翻轉繞法，需 `DoubleSide` 或翻轉索引，接手請驗） | 西席為左側、東席為右側，依桌面朝向決定誰鏡像 |
| 膚色變體 | 用材質色倍率，不另做網格 | 避免 10 份模型 |

### 3.3 寫實的具體定義（避免「寫實」變成口號）

以真實參照驗證，不憑印象：

1. 手掌長寬比與指長比（中指約掌長的 0.8～0.9；食指略短於無名指或相近，接手以照片為準）。
2. 指節三段的長度遞減（近：中：遠約 0.55：0.3：0.15 一類的遞減，以照片為準），關節處略粗。
3. 拇指根部（魚際）的隆起與拇指外展角度。
4. 手背的骨節弧度與掌心的凹。
5. 指尖與指甲的形狀（不圓潤、不Q版；符合「不可愛」）。

「寫實」的上限受**無貼圖**限制：靠形狀與頂點色暗部，不會是照片感。接受這點，不要為此去碰貼圖管線（藍圖 §2.2：新貼圖管線須另裁）。

### 3.4 十個角色怎麼一眼認出是誰的手

**提案，待使用者逐項裁定**（信物與角色對應見 `table-props.js` 的 `RELIC_NAME`）：

| 角色 | 袖口主色＋手上辨識物（提案） |
|---|---|
| 收驚婆 | 紅線手繩；較老的膚色與手背紋理 |
| 當鋪 | 袖套＋指上一枚算盤珠色戒指 |
| 組頭 | 袖口外翻、拇指上一圈墨漬 |
| 青面攤主 | 偏灰青的膚色與骨節較突 |
| 紅衣婆婆 | 紅袖、指甲暗紅 |
| 斷手書生 | 握筆繭與墨漬；**缺整隻手**（D5 已裁，做法見 §8.1） |
| 獵人 | 皮護腕、手背舊疤 |
| 孝女白琴 | 白麻袖、較年輕的膚色 |

## 4. 動作（三段）

與賽局狀態的關係：**賽局狀態機仍是權威**（`bid`／`mark`／`reveal` 照舊算），手只是把同一件事演得更像；籌碼與令牌的位置仍由 `table-props.js` 算，手去「對準」它們，不能反過來讓手決定結算。

| 動作 | 對應事件 | 內容（提案） | 時序對齊 |
|---|---|---|---|
| 推 | `bid(seat, slot, amount)` | 手從席位伸出，掌根壓住錢柱推到槽前，再縮回席位外 | 原籌碼飛行 0.42 秒；錢的終點不變，取代拋物線 |
| 拍 | `mark(seat, slot)` | 握令牌舉高（RISE）→ 拍下（SLAM_MS 0.30）→ 微顫 → 收 | 落地那一幀仍由令牌發 `ys:mark-slam`，音效不得另猜 |
| 收 | `reveal(slot, winnerSeat)` | 敗方手掌向下、五指扒攏把錢拖回席位；勝方手停一拍 | 原 0.22 秒延遲＋0.42 秒返回 |
| 閒置 | 無事件 | 手收在畫面外或只露袖口 | 不得遮 HUD／拍品 |

硬性要求：

- **可跳過、可縮時**：跳過演出時，手與錢直接跳到結束姿態，結算不變（藍圖 §2.3）。縮時與原速的證據分開記。
- **決定性**：不耗亂數；同一事件序列產生同一手勢序列。
- 同一席、同一格重複出價是**覆寫**（現有 `bid` 行為），手不能疊出兩隻。
- 熱座交棒／清場（出價歸零）要能立即把手收回。
- 直式（`P`）版面座標另一組，兩種版面都要驗。

## 5. 後景暗影人影（B）

- **只做三席**：北、西、東。南席是玩家自己，只有那隻手。
- **不是平面貼片**：有體積的低面數人影（肩、頭、帽／髮型輪廓），**每個 ≤200 三角形**，暗色＋霧色，不接受燈光細節；理由見 §2 最後一點。
- 位置：各席席位後方，落在**掏空窗內**，不得蓋住托盤、拍品與 HUD 安全區。
- 辨識：靠**輪廓**（頭飾／帽／髮／肩線）區分角色，不靠臉。紙紮感（竹篾紙骨、剪紙折痕）可放在輪廓邊緣的頂點色帶，不加貼圖。
- 對決模式：隨 `group` 一起 `setVisible(false)`。
- 必須重跑取景相關檢查（藍圖 §2 的「依 HUD 空間自動退鏡」），人影不能改變鏡頭行為。

## 7. 驗收（草案，**需使用者凍結**）

1. **硬指標**：draw call 增量 ≤ 席數（≤4）＋人影（≤3，若併批則更少），桌面 draw 不得失控；每隻手 ≤1,500 三角形、每個人影 ≤200；A1 相對效能 gate（perf32／perf128）不得由綠轉紅；`trace-eq` 相等；取景矩陣（1599）不變差。
2. **行為**：三動作各自到位——指尖不穿錢柱／令牌（取樣檢查）、收手後不遮 HUD；`P`／`L` 兩版面；跳過與縮時結算不變；熱座清場即收。
3. **辨識（讀者盲讀）**：仿 A2 做法，6 位讀者看桌面截圖，「這是誰的手」靠袖口＋配件答對 ≥5/6；另問「這隻手像塑膠人偶／像真手／跟紙紮妖放一起突不突兀」。
4. **退場閘（關鍵）**：**單隻手原型階段**就做第 3 點的「突不突兀」。讀者多數判突兀 ⇒ 停下回報使用者，選項是：縮成寫實比例＋紙紮質感（雲端 session 原建議）、或維持寫實但調整光與色讓它與桌面融合。**不要先做完四席才發現不對。**
5. 結果寫成「觀察到／未觀察到／未驗證」，不宣稱大作水準（沿用 PLAYER_EXPERIENCE_BLUEPRINT 口徑）。

## 10. 風險

- **風格衝突**：寫實人手 vs 紙紮妖（§7 第 4 點閘）。
- **效能**：蒙皮 mesh 每席一個；人影也吃 draw call；A1 gate 要重跑。
- **低多邊形寫實的上限**：容易落在「塑膠人偶」與「恐怖谷」之間；參照與頂點色暗部是唯一手段。
- **遮擋**：手與人影都可能蓋到拍品或 HUD；取景自動退鏡要重驗。
- **文化與敘事**：D5 斷手書生、老人膚色等，避免刻板化，由使用者裁定。
- **工具假設**：anyCreature 能輸出本案需要的帶骨人手、Modly 的輸出格式，都是**未驗證的假設**。
