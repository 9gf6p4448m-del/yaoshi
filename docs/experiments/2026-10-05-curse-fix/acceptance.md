# v0.60.1 詛咒轉移修正驗收條件（動手前凍結）

基準：origin/main=cf7b5008（v0.60.0，線上）。使用者 10-05 試玩回饋：詛咒「看起來像拿走」（與 v0.60.0 盲讀 r1–r3 一致）。
使用者裁定：按建議＝**砍掉「按住後拖回」那段**：紅包推過桌心、按在受害者面前就停住，受害者手抖、紙繩纏腕，之後法寶留在受害者席前（再依既有終態隱藏）；A＋C 其餘設計不動；不動一般得標、不動手尺寸（使用者：手不會太小）。
本卷盲讀為新卷新輪次（輪次歸零），條件由主對話在動手前訂定。

## 條件（紅＝什麼實作會讓它變紅）
1. trace 等價：對 cf7b5008 的 trace(1..20) 逐位元組相等（GRAB_ON 開／關皆是）、Math.random 計數 0。紅＝動到引擎。
2. 終點語意：詛咒轉移的法寶**在受害者席前停住的最後位置，與「離開受害者席前」的位移＝0**——即整段時間序列中，法寶位置與施放者席距離「不再回頭靠近施放者」：以法寶到受害者席點的距離 d(t)，要求 d(t) 在按住階段後單調不增（容差 0.01），且最終 d≤既有終點容差。紅＝仍有拖回（d 回升>0.01）。基準 cf7b5008 預期判紅。
3. 時長 ≤1300ms（落定），跳過仍在下一幀到終態、四手不可見（沿用 v0.60.0 條件 6 的治具，30/30）。
4. 紙繩 C：仍只在被按住階段出現、幾何預建（掃描 `new THREE.TubeGeometry` 仍 1 處、每幀重建 0）、844 寬繩粗≥3px；受害者手在被按住階段仍抖。
5. 不退步：v0.60.0 條件 2/3/4/5/6/7/10/11 的治具對新版重跑全過（一般得標未動：落定 1267ms、HUD 重疊 0px、穿拍品 0、擺錢逐幀等價 2080 幀、`?grab=0` 對基準逐像素 0）。
6. 盲讀（fresh agent，無對話史，答案鍵另存）：看詛咒連拍條答「這件東西最後在誰面前／是誰塞給誰」，北塞南、西塞東**2/2**；同時問「是被拿走還是被塞過來」，須答「被塞過來」2/2（使用者的原始抱怨就是被讀成「拿走」）。最多 3 輪，第 3 輪未過停手問使用者，不得自行調標。
7. 全套測試綠；本卷只准改清單內斷言：與「拖回」直接相關的 tests/grab-motion.test.mjs、tests/tools/grab-probe.mjs（詛咒段）；其餘測試被迫改＝停手回報。版本釘 tests/ui-hierarchy.test.mjs 0.60.0→0.60.1 屬版本字串連動（本卷預先列入）。
8. 版本 v0.60.1（VERSION／RELEASE_VERSION、各 ?v=）。送達：推 main 前先告知使用者，推後 curl 線上版本與 Pages built 時間。
