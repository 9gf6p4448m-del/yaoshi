## 做了什麼
- `js/duel-figures.js`：n≥3 的列陣分排（n=3 一排三尊；n≥4 每排兩尊 → 4/6/8 尊各 2/3/4 排，排距 0.55），整排不再釘在 DOM 欄位中心，而是在「中線＋0.22 ～ 桌心 2.15」的可用區間內擺，用該排最內／最外兩尊各自的腳印當邊界、排內最小間距 0.55，塞不下才縮 step；奇數排往外錯半格。**n≤2 走原路徑**（R-4 逐尊 Δ＝0）。
- `index.html`：招式字幕改 `pwMoveCap`——「**出招方名**・法寶：招名」＋第二行效果說明（`TRAITS.desc`），class 帶系色（`f-*`，字色）與側別（`side-A|B`，靠出招那一側）；VERSION 0.34。
- `js/trait-fx.js`／`js/renderer.js`：招式期間戲台燈組往出招方質心移 0.6 倍（約 0.7 單位，指數收斂 150ms 內到位），收工回位；SKIP／cancel 立刻回位。
- 治具：`duel-perf.mjs lineup`（合成 NvM，用不在真對決裡的兩個座位避開撞擊位移；量腳印投影出桌、兩側間隙、最遠 r、同側最近距）；`duel-drive` 錄音機記每筆招式的字幕字／class／`#duel` 捲動高度；`traitfx-drive` 加 `focus` 判定；治具頁 `positions()`。

## 中途修過的兩處（第一版沒過）
1. 第一版把整排釘在欄位中心、用全側最大腳印夾寬：欄位中心只有 0.90／1.08、腳印 0.16–0.66 → 排被壓到 minPair 0.21。改成可用區間＋每排內外腳印。
2. 第二版每排兩尊但排內距離只剩 step0（n=8 時 ≈0.36）→ 加 rowMinStep 0.55。
3. R-1／R-4 的量法被真對決的撞擊位移污染（1v1 差 0.11）：合成對決改用不在對決裡的座位；R-4 改在治具頁量。
