## 結論先行

**10 個角色裡有 5 個是「真弱」（紅衣婆婆、斷手書生、閭山法師、大家樂組頭、陰間當鋪）、1 個「量法偏」也同時是唯一的「強」（收驚婆）、4 個正常；(a) 十個角色全部重現 `roles-res0.md` 在 ±2pp 內（最大偏 +0.80pp）。**

但**「量法偏」與「被動真弱」都不是主因**——把整包拆開之後，勝率 5%～44% 這個分布的**最大單一來源是 `ROLES.ai` 的 `aggr`／`spite` 本身**：把角色的被動、AI hook、起始壽命全部關掉、只留 `ai` 三個數字，勝率就已經從 18.96%（斷手書生 aggr 1.0／spite 0.4）散到 30.95%（收驚婆 aggr 0.3／spite 0.1），跨距 12pp。而且**有四個角色的 AI 風格 hook 本身是負資產**（青面攤主 −5.61pp、斷手書生 −7.42pp、閭山法師 −8.77pp、陰間當鋪 −11.04pp）——它們不是「被動太弱」，是**自己的 AI 打法在害自己**。

三個要先給使用者知道的機制發現：

1. **有兩個被動掛在「已經不決定勝負」的算式上**（§0.6）：`PAPERWAR_ON` 預設開之後 `power()` 只剩顯示用途，而斷手書生的「同系 ≥4 件 +4」與閭山法師的「詛咒品戰力視為 0」都只改 `power()`。實測把紙紮夜戰關掉，這兩個被動的價值分別從 −0.38pp→+1.33pp、+0.08pp→+2.87pp（§4）。
2. **青面攤主的跟標 AI hook 在座位 0 是死碼**：`onAiValue` 的迴圈寫 `if(q.ai||…) continue`，座位 0 是唯一的非 AI，於是永遠沒有 `q` 通過——n=2000 實測 317,474 次呼叫、**0 次真的改到估值**（§3 M2 附表）。這是設計上「AI 青面追殺人類」的寫法，不是 bug，但代表玩家自己選青面時這一項完全不存在。
3. **座位 0 有系統性約 5pp 的劣勢**，來源是 `playPolicyGame` 的「唯一的真人一死，整局立刻結束」（`index.html:5100` `if(!humanN…) break`）——AI 席因此多一條「等東家先死、比壽命就贏」的獲勝路徑，座位 0 沒有。M3 六隻裡四隻座位 2 比座位 0 高過 3pp（§5）。

提案（§7）**只寫不做**：5 個真弱角色各 2 個選項，預估 +1～+7pp，全部等使用者裁。

### 0.2 四種量法（M1）

| 變體 | 座位 0 的出價 | 被動 |

**`policyAiLike` 到底吃不吃 `ROLES.ai`？——不吃。** `index.html:4939-4943`：

```js
function policyAiLike(p){
  const saved=p.ai; p.ai={aggr:0.7,spite:0.15};
  let b; try{ b=aiBids(p); } finally { p.ai=saved; }
  ...

```

它把 `p.ai` **覆寫**成寫死的 `{aggr:0.7,spite:0.15}` 才呼叫 `aiBids`，`markReact` 連欄位都沒有

角色自己的 `aggr 0.3~1.0`／`spite 0.1~0.6`／`markReact avoid|contest|ignore` 一項都沒生效。
`aiBids` 讀 `p.ai` 的三個位置：`index.html:2180`（`p.ai.spite` 決定毒標）、
`index.html:2229`（`p.ai.markReact` 決定對「被別人盯的拍品」加價還是退避）、
`index.html:2253/2257`（`p.ai.aggr` 決定出價金額與押命標機率）。

### 0.3 「被動」欄位清單（凍結檔要求逐欄位說明）

`ROLES` 一筆的所有欄位（實測盤點見 `docs/experiments/2026-09-07-role-measure-evidence/role-fields.txt`）：

| 欄位 | 算不算被動 | 理由 |
|---|---|---|
| `id`／`name`／`av`／`pool`／`desc`／`lines` | ✗ | 純呈現與索引，不進任何結算式 |
| `ai:{aggr,spite,markReact}` | ✗（是變體 b 的**自變數**） | 這是「AI 出價風格」，不是玩家被動；把它一起關掉就分不出「量法偏」與「被動弱」 |
| `hooks` 裡的 `onAi*`（`onAiValue`／`onAiPlan`／`onAiAmount`／`onAiCurse`／`onAiExtraBids`） | △ | 只在 `aiBids()` 內觸發（GUIDE §11.1），**真人玩家永遠吃不到**。凍結檔 M1(c) 字面要求「清 `hooks`」＝連它一起清，所以 (c) 混進了「AI 風格 hook」這一項；本報告另立 **(c2)** 只清非 `onAi*` 的 hook 來拆開 |
| `hooks` 裡的其餘 hook | ✓ | 玩家被動的實作處（GUIDE §11.8） |
| `traits` | ✓（但**本專案 10 個角色一個都沒有**） | `traitMax()` 讀的靜態數值特性 |
| `flags` | ✓（但**本專案 10 個角色一個都沒有**） | `hasFlag()` 讀的靜態布林特性 |
| `life0d` | ✓（但另立 (cL)(dL) 對照） | 起始壽命位移（`index.html:784` `roleLife0=R=>CFG.LIFE+(R.life0d||0)`）。**算被動的理由**：它是角色不對稱的一部分、玩家實際感受得到（收驚婆起始 44、閭山 42、爐主 52），而且設計上明擺著是「強被動的對價」；**不算被動的理由**：它不是一條「能力」，關掉它等於同時改了角色的資源基準線，會讓 (b)−(c) 這把尺量到兩件事。兩邊都有道理 ⇒ **兩種都跑**（(c)/(d) 含 life0d、(cL)/(dL) 保留 life0d） |
| `order` | ✗ | 只影響同一次 `applyHooks` 內多個 effect 的先後；`hooks` 清空後無作用（只有陰間當鋪有 `order:95`） |

**必須先講清楚的兩個口徑瑕疵**（不是實作瑕疵，是「被動」這個詞本身在這個引擎裡不乾淨）：

1. **有兩個「玩家被動」同時也會改 AI 自己的出價**：大家樂組頭的 `onBidCap`（保守標上限 ×1.5）與
   陰間當鋪的 `onBudget`（總額上限＝壽命+8）——`aiBids` 自己就會呼叫 `consCapFor(p)`／`budgetFor(p)`
   （`index.html:2166`、`2256`），所以關掉它們同時削掉了 AI 的出價能力。這兩隻的「被動貢獻」欄位
   天然含 AI 行為成分，(c2) 也切不乾淨。
2. **普渡爐主的 `onReveal`（開標看得到標書型態）在 headless 模擬裡貢獻恆為 0**：`showTypes` 只被
   UI 的開標畫面消費，`playPolicyGame` 這條路根本不讀它。所以爐主的資訊型被動在本卷的所有數字裡
   **一律量不到**——它的價值只存在於真人對局。

### 0.6 一條貫穿全卷的機制發現：有兩個被動掛在「已經不決定勝負」的那條算式上

`index.html:3158-3159` 的註解字面寫著：

```js
/* 《紙紮夜戰》：PAPERWAR_ON 時改由三拍自動戰決勝負與傷害，power() 只留給 UI 當行情顯示。 */
```

`CFG.PAPERWAR_ON` 自 2026-09-06 起**預設為 true**（`index.html:568`）。而 `power()` 是
`onItemValue`（逐件估值）與 `onPowerCalc`（`itemSum`／`resonance`／`flat`）唯一的消費者
（`index.html:2133-2147`）。所以：

- **斷手書生**的「同系 ≥4 件該系共鳴額外 +4」寫的是 `ctx.flat+=4`。共鳴接進紙紮夜戰的那條路
  （`pwResLv`，`index.html:2715-2722`）**只讀 `ctx.resonanceMul`，不讀 `ctx.flat`** ⇒ 這個被動
  對紙紮對決的勝負與傷害**完全沒有作用**。
- **閭山法師**的「袋中詛咒品戰力視為 0」寫的是 `onItemValue` 把 `ctx.value` 設 0。紙紮夜戰裡
  詛咒品的懲罰改成 `m-=sd.curses`（`index.html:2889` 詛咒纏身：每件詛咒品該側 atk 修正 −1），
  數的是 `buildArmy` 回傳的 `curses` 件數（`index.html:2697`），**跟 `power()` 無關** ⇒ 這個被動
  對紙紮對決同樣沒有作用。

`power()` 現在還留著的用途只剩：毒標／收祟挑「戰力最高的對手」（`index.html:2173`、`2179`、
`strongestFoe`）、獵人 AI 的追分估值（`index.html:919-920`）、獵人被動的 `pwRaw/plRaw` 判準
（`index.html:3184`）、`finalPower` 統計與 UI 顯示。也就是說這兩個被動現在**只剩「把自己的帳面
戰力推高／推低，因而改變自己被毒標鎖定的機率」這一個副作用**——斷手書生的 +4 讓它更常被鎖定。

**這不是推論，有實測對照**（`--paperwar=0` 把紙紮夜戰關掉退回舊的戰力比較路徑）：見 §4 的
「PAPERWAR 對照」表。

## 6. M4 分類

門檻照凍結檔，不得自訂：真弱＝被動貢獻 ≤+1pp 且 (b)<20%；量法偏＝(b)−(a) ≥+5pp；強＝被動貢獻 ≥+8pp；其餘正常。被動貢獻＝(b)−(c)。

## 7. M5 提案（每個真弱角色 2 個選項，只寫不做）

**尺的來源**（全部是本卷 n=10000 實測）：
- **起始壽命**：0.9pp／點（五隻實測 0.64～1.08）
- **同型被動天花板**：`onBidEff` 型（青面，生效率 32%）＝+4.48pp；`onBattle` 奪寶型（獵人，生效率 6.2%）＝+6.53pp；`onNightEnd` 回血型（收驚婆，生效率 50%）＝+22.23pp
- **共鳴等級**：`resonance-gate` R2′ 實測「共鳴每提一級平均位移 +5～+15pp」（`docs/IMPLEMENTATION_GUIDE.md` §11.19 第 6 點）

估值一律是**量級不是預測**；每一條做出來都要再跑一次本卷治具才算數。硬規則 3：**`index.html` 一個字都沒改，全部等使用者裁。**

### 7.1 紅衣婆婆（(b) 17.90%、整包淨值 −7.91pp）

診斷：唯一的玩家被動「被毒標塞中 ⇒ 下手者 −2」生效率只有 12.7%，而且**要等別人先毒她**；四個記仇 hook 全部只餵 AI，玩家拿不到任何東西。

- **甲（改被動數值）**：`onWinItem` 改成「被毒標塞中：下手者 −2、**紅衣自己 +2**」。觸發率不變（12.7%），單次收益翻倍。尺＝孝女白琴 `onBidSettle`（生效率 19.1%、每次 −1）＝+5.95pp；紅衣觸發率約其 2/3、單次量相當 ⇒ **估 +1～+2pp**。
- **乙（換觸發條件：把記仇帳本接到玩家側）**：新增 `onBidEff`——對「仇恨值最高的對手的主力陣營」拍品，比價 `+min(4, grudge)`。記仇帳本已經在跑，只是玩家吃不到。尺＝青面同型 `onBidEff +2`＝**+4.48pp**（生效率 32%）；紅衣觸發面窄一些但加成上限更高 ⇒ **估 +2～+4pp**。

### 7.2 斷手書生（(b) 11.36%、整包淨值 −14.51pp）

診斷：玩家被動 −0.38pp（**掛在紙紮夜戰之後已不決定勝負的 `power()` 上**，§0.6／§4）；AI 風格 hook −7.42pp。

- **甲（把被動搬到活的那條路）**：`ctx.flat+=4` 改成寫 `ctx.resonanceMul`（`pwResLv` 只讀 `resonanceMul`，`index.html:2715-2722`）——同系 ≥4 件時該系共鳴等級 ×1.5。生效率已知 19.2%。尺＝共鳴每提一級 +5～+15pp × 生效率折扣 ⇒ **估 +4～+8pp**。**這是本卷唯一一個「不改數值、只改接線」就能救的被動。**
- **乙（換觸發條件，改走比價）**：門檻 4→3 件，效果從「戰力 +4」改成 `onBidEff` 鎖定系拍品比價 −2（買得更便宜）。尺＝青面 `onBidEff` +4.48pp、門檻放寬會提高觸發率 ⇒ **估 +3～+5pp**。
- 提醒：這隻真正的大洞是 AI 風格 hook 的 −7.42pp，不在 M5 範圍（§8 待裁 1）。

### 7.3 閭山法師（(b) 6.16%、整包淨值 −18.42pp）

診斷：`life0d −8` 值 −8.65pp；AI 風格「收祟」（壽命 >10 就一律買下詛咒品，生效率 80.8%）值 −8.77pp；玩家被動 +0.08pp——因為紙紮夜戰扣的是 `m -= sd.curses`（每件詛咒品該側 atk 修正 −1，`index.html:2889`），數的是**件數**，跟 `onItemValue` 改的 `power()` 無關。**它的「免疫」在現行對決引擎裡沒有對應的實作。**

- **甲（起始壽命）**：`life0d −8 → −2`（起始 42 → 48）。尺＝它自己實測的 1.08pp／點 × 6 點 ⇒ **估 +6.5pp**（全卷最有把握的一條）。
- **乙（把免疫接到紙紮側）**：讓閭山的「詛咒纏身」`m -= sd.curses` 視為 0——實作上給 `ROLES.lvshan` 一個 `traits.curseWard`、`pwMod` 讀它（引擎要開一個掛點；`traits` 現在 10 隻都沒用到，正好）。這樣「免疫詛咒」才第一次真的存在。尺＝把玩家被動從 +0.08pp 拉到獵人級（+6.53pp）當上界、袋中詛咒品件數是折扣 ⇒ **估 +3～+6pp**。
- 附帶：`onBidSettle` 的「獨力收祟減半」生效率只有 4.9%；若要救它，拿掉 `nBids===1` 是最小改動。

### 7.4 大家樂組頭（(b) 19.53%、整包淨值 −6.33pp）

診斷：**玩家被動本身是 −3.08pp 的負資產**，全表唯一。來源＝`onNightEnd` 的「夜末得標 ≥2 件 +2、掛零 −2」：生效率 55%，但它的 AI 打法是「每夜標 3 件、每筆 ≤4」，小額標很容易全部落標 ⇒ **罰則比獎勵常發生**。另一半 `onBidCap ×1.5` 生效率 99%（幾乎每次都改到上限）卻換不到勝率。

- **甲（改被動數值）**：拿掉「掛零 −2」，只留「連中 ≥2 件 +2」（或把 −2 降成 −1）。尺＝把整個玩家被動關掉（c2）就回到 22.61%，即這條罰則加 `onBidCap` 合計拖累 3.08pp；只拿掉罰則 ⇒ **估 +2～+3pp**。
- **乙（換觸發條件：讓「分散」真的換得到東西）**：`onBidCap` 從「上限 ×1.5」改成「**每夜第 2 件之後的保守標免掛號費（`CFG.BID_FEE`）**」——直接補貼多標的成本，而不是放寬一個本來就沒咬到的上限。尺＝`onBidCap` 生效率 99% 卻換不到勝率，代表上限不是瓶頸、成本才是；沒有同型可比 ⇒ **估 +1～+3pp（信心最低的一條，做出來一定要重跑）**。

### 7.5 陰間當鋪（(b) 12.30%、整包淨值 −14.62pp）

診斷：`life0d −4` 值 −3.54pp；AI 風格「詐術喊到估值全額」（`onAiAmount`，生效率 80.5%）值 **−11.04pp**；玩家被動 +0.73pp——「典當保命」三條路徑加起來 n=2000 局只觸發 1,521 次（每局 0.76 次），而且只保住 1 壽命，下一夜多半還是死。

- **甲（改被動數值：讓典當真的救得了命）**：典當從「保住 1 壽命」改成「**保住 8 壽命**」（或次數 1 → 2）。尺＝0.9pp／點 × 多給的 7 點 × 觸發折扣 ⇒ **估 +2～+4pp**。
- **乙（起始壽命）**：`life0d −4 → 0`（起始 46 → 50）。尺＝實測 0.89pp／點 × 4 點 ⇒ **估 +3.5pp**。
- 提醒：這隻的大洞是 `onAiAmount` 的 −11.04pp（§8 待裁 1）。

## 8. 三件超出 M5 範圍、但量到了、請一併裁

1. **四個角色的 AI 風格 hook 是負資產**（青面 −5.61／斷手 −7.42／閭山 −8.77／當鋪 −11.04pp）。這些是「角色個性」不是被動；改它們會改變 AI 對手的手感，屬硬規則 3 的策略邏輯，必須使用者裁。**但如果目標是拉平角色勝率，這是比動被動更大的槓桿。**
2. **`ROLES.ai` 的 `aggr`／`spite` 本身造成 12pp 跨距**（§2.4）。`spite ≥0.5` 的三隻與 `aggr ≥0.85` 的三隻全部落在後段。要不要把 `spite` 上限往下壓是設計取捨（`spite` 高＝愛毒別人，那是角色個性），請使用者裁。
3. **座位 0 的 −5pp 系統性劣勢**（§5）。這是**量法**問題不是平衡問題，但它污染了所有既有的角色勝率表。修法有二：① 讓 `playPolicyGame` 在真人死後繼續跑完（改引擎，會破壞既有 trace 等價基準）② 平衡量測改用「同一角色輪流坐四個座位取平均」的口徑（只改治具）。**建議 ②。**

## 11. 沒做到的、假設過的、覺得凍結檔有問題的

### 11.1 沒做到

1. **M3 只做了 6 隻**（凍結檔要求前三＋後三，已滿足），沒做全部 10 隻；四隻超過 3pp 之後我沒有再往下量「座位 1 與座位 3 之間差多少」，所以「座位 0 劣勢約 5pp」這個數字是從 M3 六批的四席勝率**橫向平均**來的（21.5% vs 26.6%），**不是一個專門設計的對照實驗**。要當結論用得再做一次。
2. **`onReveal`（普渡爐主的資訊型被動）本卷完全沒量到**，因為 headless 不走那條路。爐主的真實強度可能高於 28.90%。
3. **被動生效計數的偵測器有已知漏網**：它比的是 `ctx` 的淺層欄位，寫進 `ctx.p.grudge`／`ctx.winner._ztN` 這類巢狀欄位的 hook 會被記成 0 次（紅衣的三個記仇 hook、大家樂的 `onWinItem`）。表裡已逐格標示哪些 0.0% 是漏網、哪些是真的死碼。
4. **§7 的預估 pp 沒有任何一條被實作驗證過**——硬規則 3 不准改角色數值，全部是「用已量到的同型被動當尺推出來的量級」。信心最低的是 7.4 乙（沒有同型可比）。
5. **`dL` 變體有跑但沒有單獨開一張表**（數字在 `AGG-n10000.md` 與各 JSON 裡）；它與 (d) 的差就是 `life0d` 在統一量法下的值，結論與 (cL)−(c) 一致，沒有另外的資訊。

### 11.2 假設過

1. **(b) 的定義**：把 `policyRoleAi` 寫成與 `policyAiLike` 同構、只換塞進去的 `p.ai`（含 `markReact`）。這假設「角色自己打」＝「`aiBids` 吃它自己的 `ai`」。M3 的座位 2 是這個假設的獨立驗證：座位 2 是真的 AI 席、真的吃 `ROLES.ai`。
2. **「被動」的界線**：`onAi*` 算 AI 風格不算玩家被動（GUIDE §11.1：只在 `aiBids` 內觸發、真人吃不到）。但**大家樂的 `onBidCap` 與當鋪的 `onBudget` 雖是玩家被動，`aiBids` 自己也會呼叫 `consCapFor`／`budgetFor`**，所以這兩隻的「玩家被動」欄位天然含 AI 行為成分，(c2) 切不乾淨。
3. **`life0d` 算被動**：兩種都跑了，M4 分類在兩種口徑下相同。
4. **M3 的種子條件化**：只取「受測角色恰好被抽到座位 2」的種子（命中率約 1/9），假設這個條件與後續牌堆洗牌無關。`rosterSeats` 在洗牌之前消耗 rng，所以條件會改變後續亂數流，但改變方式是任意的、不是系統性的。

### 11.3 覺得凍結檔有問題的三條

1. **M4 的「量法偏 ≥+5pp」是單向的**。實測有 5 隻是反方向偏（−2.9～−7.0pp），而且那才是主流。這條門檻只抓得到「舊表低估」，抓不到「舊表高估」——而 `roles-res0` 對五隻角色是**高估**的。建議下次改成 `|(b)−(a)| ≥5pp`。（我**沒有**動這條門檻，表照凍結檔定義出，只是把反方向數字另外列出。）
2. **M4 的「真弱」把兩種病混成一類**。「被動貢獻 ≤+1pp」同時涵蓋「被動可有可無」與「被動是負資產」，處方完全不同。報告用 §2.2 的三欄分解把它們分開，但**分類欄位仍照凍結檔輸出**。
3. **M1(a) 的「重現 `roles-res0` ±2pp」其實驗不到治具對不對**。`roles-res0` 是 n=2000（SE 0.85pp）、而且是**別的引擎版本**跑的；±2pp 這個帶寬寬到即使治具有中等程度的錯也照樣會過。真正有鑑別力的是我另外補的兩件：① 拿掉全部計數包裝的原生 `runMany` 對照（`naked-diag-check.txt`，同一個數）② 把治具指向 `roles-res0`／`res1` 當時的引擎版本各跑一次。建議下次把 M1(a) 的驗法直接寫成「原生 `runMany` 對照」。

### 11.4 M2 那條失敗模式在本專案是空的

凍結檔 M2 寫「什麼實作會讓它紅：清 hooks 但 traits／flags 沒清」。實測 10 個角色**一個 `traits`、一個 `flags` 都沒有**（`role-fields.txt`），所以這條檢查在這裡不可能紅——不是我通過了，是它無從失敗。真正有鑑別力的是另外兩件：hook 計數 (b)>0／(c)=0，以及影子計數證明呼叫點在 (c) 仍被走到。
