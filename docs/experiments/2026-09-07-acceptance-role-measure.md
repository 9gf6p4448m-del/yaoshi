# 驗收凍結檔：角色量法＋被動消融卷（2026-09-07；只量測、不改數值）

基準 SHA：`cfbb30a`。起因：角色勝率分布 5%～38%（`docs/experiments/2026-09-07-balance-evidence/roles-res0.md`，n=2000、座位 0 用統一的 `policyAiLike`），使用者判斷「有些角色的被動真的很弱」；我判斷尺可能也偏（角色的 `ROLES[x].ai` 出價風格在座位 0 沒被用到）。本卷把兩件事拆開量：**量法偏**（風格量法拉回多少）與**被動真弱**（被動關掉少多少）。

## 範圍
- 只新增 `tests/tools/role-measure.mjs`（與必要的輔助 mjs）、報告 `docs/experiments/2026-09-07-role-measure-report.md`、證據目錄 `docs/experiments/2026-09-07-role-measure-evidence/`。**不得改 `index.html`／`js/`**（引擎、角色數值、AI 參數一律不動；若量測需要開關，用載入後記憶體覆寫 `G.ROLES[x].hooks={}` 之類，不寫檔）。
- 提案（每個「真弱」角色 2 個加強選項＋預估 pp）只寫進報告，**不實作**（硬規則 3，等使用者裁）。

## 驗收條件（動手前訂；門檻不得為了過而調）
- **M0 引擎零改動**：`git diff --stat cfbb30a` 只含上列新增檔；`trace(1..20)` 與基準逐位元組相等（治具只讀）。
- **M1 四種量法 × 10 角色，n=10000（座位 0 為受測角色，其餘三席隨機角色＋預設 AI，seed 1..10000 固定）**：
  (a) 基準＝現行 `policyAiLike`（須重現 roles-res0 的數字 ±2pp，證明治具對得上）；
  (b) 風格＝座位 0 的出價改吃該角色自己的 `ROLES[x].ai`（aggr／spite／markReact）——若查明 `policyAiLike` 本來就吃 `ROLES.ai`，要用實驗證明 (a)=(b)（改 aggr 0.3→1.0 勝率有變化才算「有吃」）；
  (c) 風格＋被動關（清空該角色 `hooks`／`traits`／`flags`／`life0d` 與任何被動欄位，清單要列在報告並逐欄位說明為什麼算「被動」）；
  (d) 基準＋被動關。
  輸出表：角色｜(a)｜(b)｜(c)｜(d)｜量法偏＝(b)−(a)｜被動貢獻＝(b)−(c)｜SE（n=10000 時 ≈0.5pp）。
- **M2 消融開關的鑑別力**：對被動最強嫌疑（收驚婆 38%）做 (b)→(c) 必須掉 ≥3pp，且 hook 觸發計數在 (b) >0、在 (c) =0（活性＋開關真的關了）；對「無被動可關」的角色（若有）明說。什麼實作會讓它紅：清 hooks 但 traits／flags 沒清（被動仍在），或 hook 計數器沒接。
- **M3 座位控制**：前三名與後三名角色另量座位 2（n=10000，(b) 量法），與座位 0 差 ≤3pp 才可說「與座位無關」；否則報告要標「含座位效應」。
- **M4 分類（報告必填，每角色一行）**：真弱＝被動貢獻 ≤+1pp 且 (b) <20%；量法偏＝(b)−(a) ≥+5pp；強＝被動貢獻 ≥+8pp；其餘正常。每類附證據列。
- **M5 提案**：每個真弱角色給 2 個加強選項（改被動數值、或換觸發條件），各附「預估 pp 與依據（用 (c)→(b) 的差當尺）」；不實作。
- **M6 報告格式**：結論先行（一句話：幾個真弱、幾個量法偏）＋表＋分類＋提案＋治具跑法原文；證據目錄放原始輸出。

什麼實作會讓 M1 紅：座位 0 以外三席固定同一組角色（座位效應被固定）；n<10000；(a) 對不上 roles-res0。
