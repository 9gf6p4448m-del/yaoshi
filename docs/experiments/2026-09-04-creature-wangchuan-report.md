## ⑥ 這一隻踩到、下一隻會再遇到的引擎事實（六條，已同步寫進 `wangchuan.json` 的 `_traps`）

1. **★★ `part_attachment` 只看「所有頂點裡離最近環心距離減該環最大半徑」的最小值，所以四角矩形 `fin` 幾乎必擋——但只要外形加一對中點頂點就過。**
   四片帆板跨過桅杆（u 從 −0.315 到 +0.315），但 `points` 只有四個角，全都離桅軸 0.28–0.31，`checks.js` 量到「浮空 0.276」直接 BLOCK。加上 u=0 的一對外凸中點（下緣往下 0.008、上緣往上 0.008，維持嚴格凸）之後，那兩個頂點離桅軸只有 0.010，一次就過。這是 `boat` ⑥-2「桶形凸多邊形」的同一條，但**適用面更廣**：任何「跨過宿主的大板子」都要在跨過宿主的那一段補頂點。
   **副作用是好的**：帆板 host 因此可以放在 `mast` **chain** 的關節上而不是鬆散關節，`part_attachment` 真的有在守——`flag` 的旗、`thunder` 的翼都掛鬆散關節，那條檢查被 `checks.js:306` 整條略過（`hostChain=null`）。

2. **★★ 主鏈臥在世界 X 軸上時，`mirror` 會把部位複製到「船的另一端」而不是「另一舷」。**
   `skeleton.js:65` 的鏡射是對 **X** 做的（`[-p[0], p[1], p[2]]`）。本隻的 hull 主鏈就沿 X 走，所以 `mirrored:true` 會把右舷的彩繪板搬到船尾去。**處置：全檔不用 `mirrored`，兩舷各寫一份**（部位數 170，但都是產生器算出來的）。連帶：`skeleton.js:59` 會給任何 `L` 開頭的鬆散關節長出 `R*` 孿生，所以本檔關節名全部避開 `L`（`bow` ⑧-1 的反向用法在這裡是陷阱不是工具）。
   **好消息**：`colors.arcs` 的左右鏡射（`compile.js:219` 的 `sym` 折疊）在這個佈局下剛好是**兩舷同時著色**，所以船腹的色帶不必寫兩次。

3. **★★ 「淺眶＋幾乎填滿的深色瞳」在暗底上讀成洞，加一個高光點才讀成眼。**
   r5 的船眼是三層（近黑襯底 0.086 → 骨白眶 0.072 → 近黑瞳 0.036），第 2 輪兩位逐字讀成「窗孔或錨孔」「瞭望窗或炮口」——**同一組幾何在 r3 是 2/2 讀成船眼**，差別只在 r5 把船身壓暗了。改成四層（**鎏金襯框** → 骨白眶 0.074 → 瞳縮到 **0.030**（露出更多眼白）→ **骨白高光點 0.013 偏左上**）之後，第 3 輪兩位逐字「白底黑瞳的大圓眼，眼周有金色鑲邊」「巨大的白色橢圓形眼睛，中央黑色瞳孔」。
   **判準：眼球的訊號不是「有瞳」，是「有高光」**——沒有高光的圓孔一律讀成孔。這條可直接套到後面所有做眼睛的隻。

4. **★ 上翹尖端上的「中線平板」要把下緣寫進鏈的中心線，不是寫在表面上。**
   `review-boat` ⑧-5 說首尾尖端要用 `fin` 平板而不是 `curve` 圓管（圓管必被讀成角），本檔照做；但第一版把板子錨在**船舷表面**（`side_point(t, 0, ±1)`），最近的一根環半徑只有 0.05 級距，`part_attachment` 量到浮空 0.052–0.072 直接 BLOCK。改成錨在**鏈的中心點**（`hull_at(t)` 的 `c`、offset z=0）、下緣寫到 v=−0.09 之後，那些頂點離環心的距離接近 0，穩過。**規則：中線平板一律用鏈中心當錨點，不要用表面點。**

5. **★★ `saturation_area` 量的是「HSV S ≥0.50 的像素面積」，降飽和度可能完全沒用；真正的大宗常是兩條 `arcs` 之間的漸層。**
   r6 破表 0.6025，我先把船腹橘由 `#a85422`（S 0.798）降到 `#9c5a33`（S 0.673）**反而升到 0.6194**——兩個值都在 0.50 門檻上方，改了等於沒改。而 `exp ≥4.5` 的方塊斷面在船側那一片平面上，sym 82.5（世界高度 −0.457·rh）與 sym 90（0）之間**跨越 46% 的船身高度卻沒有任何頂點列**，那一整片是 gouraud 內插出來的橘→棕漸層，中點色 S 仍 >0.50。
   **解法是把漸層切段**：色帶由 2 段拆成 4 段（焦黑 0–52 → 深燼褐 54–69 → 香火橘 70–79 → **風化棕 80–89**（S 0.49，剛好在門檻下）→ 基底），漸層在低飽和的中繼色上收掉。實測三種配置（同一顆模型、只換 arcs）：

   | 配置 | `sat_tq` | `sat_front` | `lum_front` |
   |---|---|---|---|
   | 2 段（r6/r7） | 0.6025 / 0.6194 | 0.6097 | 43.0 |
   | 3 段 | 0.5822 | 0.5686 | 44.2 |
   | 3 段（中繼色更暗） | 0.5368 | 0.5142 | 43.9 |
   | **4 段（出貨）** | **0.5222** | **0.4981** | 43.5 |

   另外實測過 `shading`（`gradient.bottom` −0.80→−0.45、`noise.amount` 0.22→0.06）**四種組合對 `sat` 只移動 ±0.02**，猛虎報告 ⑤-6 的「noise 把近黑擾成高飽和」在本隻不是主因——**先量再改，不要照抄別隻的歸因**。

6. **★ `colors.arcs` 在 `exp ≥4.5` 的方塊斷面上畫不出等距橫紋，橫紋要用實體 `fin`。**
   `compile.js:219` 的 `sym` 是**斷面角度**不是世界高度。實算 `sides:48`、`exp 5.2` 時，船側那一片平面上的頂點列落在世界高度 −0.826（sym 52.5）／−0.766（60）／−0.691（67.5）／−0.594（75）／−0.457（82.5）／**0（90）**·rh——列與列的間距從 0.06·rh 一路撐到 **0.457·rh**，愈靠近船側中央愈稀疏。所以：**細橫紋只能做在 sym 52–83 這一段（靠近下轉角），船側中央那 46% 高度只能用實體 `fin`**。本檔的三條彩色橫紋與整排彩繪板因此全部是 `fin`（推導寫在 `ref-wangchuan.md` §五，是**動手前**算出來的，不是撞牆後才發現）。
