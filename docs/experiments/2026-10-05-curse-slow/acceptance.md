# 詛咒轉移「太快看不清」修正驗收條件（動手前凍結）

基準：origin/main=4691a7ce（v0.60.1，線上）。版本號：排在批 1 手變體 v0.61.0 之後，暫定 v0.61.1（若順序對調則改 v0.60.2，屆時於本檔修訂記錄）。
使用者 10-05 試玩回饋：「我剛剛給別人詛咒物，是給西方的，速度快到我也看不到怎麼回事，但最後有看到我壓著他的手」＝南席施放者塞給西席。使用者 10-05 稍後確認「目前沒其他回饋」。
現況（agent 回報，v0.60.0/0.60.1）：推按落定 983ms；示意與驗收只測過北塞南、西塞東，**南塞西從未驗過**。
使用者授權決策（「你現在是我」）的代決：推過桌心約 1.3s 讓路徑看得見＋按住停約 0.7s，總長約 2.0s；做成 `CFG.CURSE_MS` 單一常數，試玩覺得拖或太快一句話調；揭卡等待由其推得，鏡頭不得在搬運途中切走。

## 條件（紅＝什麼實作會讓它變紅）
1. trace 等價：trace(1..20) 對 4691a7ce 逐位元組相等、Math.random 計數 0。紅＝動到引擎。
2. 全組合：施放者≠受害者的 12 個有序組合（南北西東各塞給另三席）逐一量，每組落定時間落在 `CURSE_MS`±10%；`CURSE_MS` 預設 2000ms（落在 1800–2200）。基準 983ms 預期全 12 組判紅。紅＝任一組落定時間在區間外或量不到。
3. 路徑看得見：推過桌心階段（開始推到抵達受害者席前）≥1200ms，該階段法寶螢幕位移每 100ms 幀間最大值不得超過基準同組的 0.6 倍（速度放慢的客觀證據；基準每組各量，貼數字）；按住停留（抵達到收手開始）≥600ms。紅＝仍是快速掠過。
4. 不穿模：手最低點≥桌面高度（0.152），手頂點進入「非被推拍品」包圍盒 0 點，12 組全過（南塞西、東塞南等遠距離與越中線組合要特別量）。紅＝穿桌／穿拍品。
5. 鏡頭：reveal-card 時間≥落定時間（搬運途中不切走）；框景納入被推的法寶與手；index.html 中揭卡前的 sleep 由 CURSE_MS 推得（不得寫死另一個數字讓兩者脫鉤）。紅＝卡片早於落定。
6. 紙繩（C）與受害者手抖：只在按住階段出現（階段外 0 幀）、844 寬繩粗≥3px、幾何預建（`new THREE.TubeGeometry` 掃描仍只有受保護處一處、每幀重建 0）；受害者手交替峰≥3。紅＝繩每幀重建或階段外出現。
7. 跳過：任意時刻 doSkip → 下一幀法寶在終點、四手不可見，12 組各量一次，30 個隨機時刻（沿用 v0.60.0 治具）；紅＝跳過後仍飛／手仍可見。
8. 一般得標不退步：落定 1267ms、HUD 重疊 0px、穿拍品 0、擺錢 2080 幀 sha256 與 4691a7ce 相同、`?grab=0` 對基準逐像素 0 差異（沿用 v0.60.0／0.60.1 治具重跑）。紅＝動到一般得標或舊拋物線。
9. 效能：每幀 p95 ≤ 基準 ×1.25（本機 Chromium 5 輪中位；iPhone 未驗須標明）。
10. 五種詛咒物各至少一組實跑連拍（冥婚紅包、魔神仔的芭樂、抓交替水符、縛靈鎖、白虎煞），確認動畫都播且不穿模（先前只跑過紅包）；結果如實列（過／問題）。
11. 全套測試綠。**預期要改的舊斷言限於**：tests/grab-motion.test.mjs 與 tests/tools/grab-probe.mjs 中寫死詛咒落定 983ms／階段時長的斷言（新斷言須對 4691a7ce 紅）；版本釘 tests/ui-hierarchy.test.mjs（版本字串連動）。清單外測試被迫改＝停手回報。★改寫清單需使用者簽核（§2.1：原斷言守的是「983ms」舊設計時長）；簽核前不得做★
12. 最終判準＝使用者真機試玩「看得懂誰塞給誰」。本卷不用盲讀當閘（v0.60.0／0.60.1 盲讀兩度未過，使用者 A 簽放寬，盲讀答錯原因已併入畫面升級卷）；但實作者須附每組合連拍條供使用者看。
13. 送達：推 main 前先告知使用者；推後 curl 線上版本與 Pages built 時間。
