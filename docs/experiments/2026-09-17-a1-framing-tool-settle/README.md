# 取景矩陣工具 `table-framing-check.mjs` 跑序依賴：診斷與處置（2026-09-17）

結論：**桌機 1280×720 的 `launch` 絕對值不只依賴跑序，同序重跑也會漂**（81 案裡 5–6 案差 108–171 px），所以「跑序依賴」是誤診——真因是逐跑的不確定性，加了每案前的鏡頭沉澱（不論「跑到靜止」或「固定 240 步」）都沒有消掉。通過／失敗判定不受影響：所有變體都 81/81，且 0.57.17 全矩陣 1599/1599。本卷停手，列入 A1 未解清單；**修前不得拿跨版本逐案分佈當等價證據**這條照舊。

## 量法

同一組案例（`--all --match=slot1:winner0`，27 件 × 3 視口＝81 案）在同一版程式碼下正序／倒序／正序再一次各跑，逐案比對 `summary.launch` 與 `terminal.beforeHide` 的四邊座標，差 >0.5 px 算相異。工具加了 `--reverse` 旗標（只影響案例順序）。原始檔：`old-*.json`（HEAD 工具）、`new-*.json`（每案前跑到相機靜止）、`fixed-*.json`（每案前固定 240 步），[order-compare.json](order-compare.json)。

| 比對 | launch 相異案 | terminal 相異案 | 最大差 |
|---|---:|---:|---:|
| 舊工具 正序 vs 倒序 | 15/81 | 1 | 179 px |
| 跑到靜止 正序 vs 倒序 | 8/81 | 3 | 179 px |
| 跑到靜止 正序 vs 正序 | 1/81 | 0 | 116 px |
| 固定 240 步 正序 vs 倒序 | 13/81 | 1 | 178 px |
| **固定 240 步 正序 vs 正序** | **6/81** | 0 | 171 px |

相異全在 desktop-1280x720、全在 `launch`（push 相位的第一個有效取樣）；terminal 幾乎不變。差值集中在 108–179 px，像是兩個離散狀態之間跳，不是連續漂移。

## 沒排除的假設（下一個接手者從這裡起）

1. 桌機視口走自動退鏡（`framing`），機位距離由紙紮「擺姿後的蒙皮包絡」決定；待機動作的相位若來自 GLB 載入當下的真實時間（不是模擬時鐘），同序重跑也會落在不同相位 → 不同包絡 → 不同 launch。驗法：在 measureCase 開頭把該尊 mixer 的時間歸零再量。
2. push 相位第一個取樣落在 `ys:reveal-slot` 之後第幾個 rAF 有兩種可能（隊列裡是否已有一個待跑的 renderer callback）。驗法：記錄第一個取樣的 `manual.now − 派事件時刻`。

## 處置

- 工具保留兩個改動：`--reverse` 旗標（診斷用）與每案前固定 240 步沉澱（讓 launch 至少不依賴上一案的鏡頭回桌狀態；不改任何判定門檻、不動 area／obstacle 條件）。0.57.17 全矩陣 1599/1599 是用這版跑的。
- 列入 A1 結案卷未解清單第 5 條；A2 每件標竿的矩陣證據只用「同版重跑穩定＋受影響案例單獨跑」判綠（與 0.57.14 起的作法一致）。
