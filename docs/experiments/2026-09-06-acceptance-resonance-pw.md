## 驗收條件（動手前訂，凍結；n＝10000、seeds 1..n）
- **R0 kill switch**：PW_RES_MODE=0 時 `trace(1..20)` 與 31504b0 逐位元組相等；M1／M2／M3 各自必不相等。

- **R2 有感但不支配**（袋對袋 duelBags）：程式枚舉「同系 3 件 vs 三系各 1 件、總 p 相等」的配對，先在 MODE 0 量基準，只留基準勝率（不計平手）落在 **40–60%** 的配對當有效對照，有效配對 **≥3 組**；各候選下成套袋勝率須落在 **55–75%**。基準不足 3 組有效對照＝該條「無法判定」，明寫。

- **R5**：既有 5 套 `tests/*.test.mjs` 綠；Playwright 對決一局（候選之一開啟）0 console error。
- **R6**：`docs/proposals/2026-09-06-resonance-paperwar.md` 存在，含三候選閘門結果表＋建議，**結尾是給使用者的裁定題，不是已改的預設**。

## §2.1 修訂紀錄：R2 → R2′（2026-09-06，使用者針對提案裁定題 2 明確同意）
- **原標準錯在哪**：R2 用 4 組「基準 40–60%」對照、要求候選落在 55–75%。duelBags 對同一對袋子是決定性的（只有月相與風位隨種子變），成套勝率只落在 49.56／74.90／100% 幾個離散階，55–75% 帶在這個顆粒度下幾乎踩不到；且 248 組候選配對只篩出 4 組有效對照（陰氣 0 組）。
- **為什麼現在才知道**：凍結時沒先量「基準的勝率分布是連續的還是離散的」（教訓 1）；第一次 n=10000 跑完看到 100.00% 與 49.56% 整齊重複才發現。
- **R2′**（同一份實作、同 n）：全部「同系 3 件 vs 三系各 1 件、總 p 相等」配對（248 組）在 MODE 0 與候選下各跑 duelBags(n)，判定 ①成套勝率平均位移落在 **+5 ～ +15pp** ②候選下成套 100% 的配對數 **≤ 基準 100% 配對數 × 1.5**。什麼實作會讓它變紅：加成太小（<+5）或太大（>+15）、把隻數當加成（100% 配對暴增）。
