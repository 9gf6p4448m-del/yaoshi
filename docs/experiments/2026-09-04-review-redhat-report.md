## ⑤ 這一隻踩到的引擎陷阱（附件五份之外的新發現）

1. **★ 最貴的一條：`type:"eye"` 帶 `anchor` 時，第二顆眼睛會長到後腦。**
   `compile.js:283-287` 的兩顆眼是 `for (const sx of [1,-1])` 配 `around: p.anchor.around * sx` 生的。用八角探針逐角讀 compiler 印的 world normal（`around` 0/45/…/315），**直立鏈的 `dir(θ) = (−cosθ, 0, −sinθ)**——0=−X 側、90=−Z 背、180=+X 側、**270=+Z 正面**。於是 `dir(−θ)` 的 **x 不變、z 翻號**：那是**前後鏡射**，不是左右鏡射。舊版把眼放在 `around: 74`，第二顆就落在 −74 ≡ 286（前），第一顆落在 74（後）——臉上只有一顆眼，另一顆在後腦。judge 量到舊版 `eye` 側視 share 幾乎為 0，就是這件事的機械痕跡，而**沒有任何 BLOCK 或 warn 會告訴你**。
   **對策：直立鏈上的眼一律不要用 `anchor`**，改走 `host` ＋ `face`／`spread`／`height`（`compile.js:289-290`），那條路的 `side = cross(up, fwd) = +X`，兩顆才真的左右對稱。同一份 spec 裡的 `fin` `mirrored` 是**世界座標鏡射**（`mirrorMesh`），行為正確，不受這條影響——所以「眉板對、眼睛錯」會同時發生，很容易誤判。
   **這條要寫進 haunt 六隻與任何直立體型的派工附件。**
2. **`around` 在直立鏈上的世界方向，必須用探針量，不能推。** `SYNTAX.md` 的註解（0=spine、180=belly）與 `shield` 報告 ⑥-1 的推論（垂直鏈 sym 180 ＝正面）**都和本隻實測不合**。做法：寫一支八角 `fin` 探針、只看 compiler 印的 `world normal` 那一行，30 秒就有答案。舊版的眉板也因此貼在後腦（`around: 70` → `faces back (-0.33,0.09,-0.94)`），那行 info 一直都印出來，只是沒人讀。
3. **收窄軀幹 → `root_containment` 連鎖失效。** body profile 一改細，掛在它上面的 `head`／`LArm`／`RArm` 根環會同時報「N% 外露」。順序是：先定 body profile，再把各鏈的根環半徑壓到「該高度 body 半徑的 0.7 倍以內」、根關節埋到體內。本隻踩了兩次（22% 與 29%）。
4. **`type:"paw"` 之後接 `curve` 當爪子，`part_attachment` 量的是 `curve` 到**宿主 volume**的距離，不是到 `paw` 的距離。** 爪子看起來從手掌長出來就好，實際 `offset` 的 z 必須落在手臂 volume 末端環的容差內（本隻 ≤0.022），否則一律 BLOCK（實測 0.029–0.034 clear）。把 `paw` 想成「也只是一個部位」就不會排錯。
5. **`sides` 一改，`colors.arcs` 的角度要跟著改。** arc 會吸附到面的角度格（`sides:10` ＝每面 36°）。從 12 邊改成 10 邊時，原本 `0–30 / 60–90 / 120–150` 的窄帶會塌掉；要改成 36 的倍數（`0–36 / 72–108 / 144–180 …`）才留得住「圓鱗窄帶」的節奏。
