## ③ 改了什麼（全部改動＝46 個數字）

**`assets/creatures/shanshen.json`，`parts` 索引 159–204 共 46 個零件（23 片 `material: zuli_gold` ＋ 23 片與之配對的 `material: rock_seam` 裂壁），全部 `host: "CragFore"`，把每個的 `offset[1]` 減 0.028。其餘一格未動。**

可完整重現的 patch（跑完 `git diff --numstat` 應為 `46 46`）：

```python
# 落檔務必用 indent=1 + CRLF，否則整檔重排成 11122 行 diff（見 ⑧-2）
import json, io, collections
P = 'assets/creatures/shanshen.json'
raw = io.open(P, encoding='utf-8', newline='').read()
d = json.loads(raw, object_pairs_hook=collections.OrderedDict)
for i in range(159, 205):
    p = d['parts'][i]
    assert p['host'] == 'CragFore' and p['material'] in ('zuli_gold', 'rock_seam')
    p['offset'][1] = round(p['offset'][1] - 0.028, 4)
io.open(P, 'w', encoding='utf-8', newline='').write(
    json.dumps(d, ensure_ascii=False, indent=1).replace('\n', '\r\n'))
```

**為什麼是 0.028、為什麼是這 46 個**：回修卷把峰／鞍部整組下沉 0.028（實測：`parts[111]` S5 山腳 y `0.0729 → 0.0449`、`parts[123]` S6 山腳 y `0.044 → 0.016`、`parts[126]` S6 峰體 y `0.0694 → 0.0414`），但金脈那 46 片的 `offset` 與 4B 出貨版**逐值相同、一格沒動**（實測比對 `git show e7b553b:assets/creatures/shanshen.json`，23 片 gold 的 dx/dy 全為 0）。所以金脈相對於岩體高了 0.028，脈的上緣頂出岩體被讀成獨立的柱。下沉 0.028 就讓相對位置逐值回到 4B。

回修卷授權的另外三個可加項**都沒動用**：脈寬窄不等（本檔已有 0.46/1.00/0.68/1.18/0.40 五段不等寬）、分岔（已有兩處）、脈色明度再拉高一階（`zuli_gold` 維持 `#edc45f`）。單一變數就過了門檻，依 Surgical Changes 不再多動。
