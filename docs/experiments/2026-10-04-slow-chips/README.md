## 3b 多出的 2 個 null 樣本查證（seat 3 slot 2 的 (2)、(2,3)）
結論：不是手追錢柱的平滑／增益（B），手追蹤本來就沒有平滑係數；是量測假象（A 型），成因是「信物避讓」讀的信物動作用牆鐘固定 0.7s（`RELIC_MOVE_MS`，不隨放慢），不是相位量。
證據（`out/t3-curve.txt`，手尖到終點水平最近距離，門檻 0.1253）：
- 基準（飛行 0.42s）：phase 0.30→0.2073、0.55→0.1852、0.73→0.1516，**phase 0.79 突降到 0.0879**，最後 0.0842（進門檻，差值 −0.0917s）。
- 新版（飛行 0.70s）：phase 0.30 起固定 **0.3977** 直到落定（最近 0.3975），從未進門檻。
- 關掉信物避讓（診斷，`--norelic`）：基準與新版**都**固定在 0.3977——那是 seat 3 的伸入界線（hand-realism 第二輪規則）把手擋住，錢自己滑完剩下的路。也就是說基準那一下「進門檻」是信物避讓在信物動作進行中（絕對時間約 0.33s）把手側移到另一條線，讓界線放行而擦進門檻；新版飛行拉長到 0.70s，同一個事件發生在別的相位，剛好沒擦進。FLY_MS 掃描：0.42 → 最近 0.0842；0.5／0.6／0.7／1.0 → 0.3975～0.3977（在 0.42～0.5 之間翻轉）。
- 因此手的追蹤沒有隨 PACE 變差，不改 `js/hand-motion.js`。
處置（不改條件）：原「null ≤ 基準」子條款**在原口徑下仍不過（45 對 43）**，列為已知待使用者裁定。另補一項不隨放慢漂移的第二檢查（不取代原子條款）：「歸一化到位」＝該格推的期間，手尖距終點第一次進到「這一段自己的最近距離＋0.02」內的時刻，比例同樣除以飛行時長。數字（`out/t3-check.txt`）：基準 64 有效／0 null、比例 −1.2877…−0.2183；新版 64 有效／0 null、−1.146…−0.2085；允許區間 −1.3877…−0.1183，區間外 0 → 過。鑑別力：手慢半拍追錢突變 → 新版比例最大 −0.0119、區間外 11 個 → 紅（`out/t3-check-mutant.txt`）。程式碼未改，故 3a、5、8、trace-eq、全套 461/461 沿用上次結果。
