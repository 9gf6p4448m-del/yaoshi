# L1a/b 水陸偷渡：驗收凍結 v0.1

2026-09-21 使用者：「按照建議接著實作」，批准 [D2 建議案](../../../plans/2026-09-21-l1-chains.md)。本段交付共通查詢與水陸一組；千眼、雙虎、配方／補件 UI、AI 估值及首次演出依既定 L1c/d 後續順序。基準 de471a2／v0.57.35。未完成平衡與整合閘門前不發布連鎖正式版。

## 規則與反例

| 情境 | 固定結果 |
|---|---|
| 接收毒標前已有非詛咒 boat＋buoy | 詛咒被銷毀，不入袋；成本與得標照常，阻擋事件僅一次 |
| 少一件／材料被移除／帶 curse 的同 ab 物件 | 無連鎖；補回有效材料即恢復 |
| 多份 boat／buoy | 水陸只啟動一次，材料不消耗 |
| 同夜先取得最後一件材料，後遇毒標 | 依拍品結算先後，即時生效；毒標先來則不能追溯攔截 |
| 已持舊詛咒 | 不清除 |
| 自行標下詛咒 | 沿用既有買下銷毀，不計連鎖阻擋 |
| 送王船／夜規送入詛咒 | 不是毒標，不攔截、不冒稱入袋通用免疫 |
| 被擋毒標的心願 | 不計 poisonHit／poisonTargets；得標、成本與其他拍賣統計保留 |
| 被擋毒標＋虎爺印／紅衣婆婆 | 不反咬、不觸發受咒加命或受咒記仇；其他已發生的競標副作用保留 |
| 被擋毒標的得標者為大家樂組頭 | 得標計數仍累加，不可略過整個得標 hook |
| 回顧／高光／台詞／聲音／道具演出 | 反映銷毀，不說塞入、不播受咒／轉移成功；歷史保留企圖目標與阻擋結果 |

## 實作契約

- CHAINS 以 ab 配方資料驅動，activeChains／chainsCompletedBy 為純查詢、零 RNG；查詢不修改袋子，不讓已啟動組合因多買副本又算新完成。
- collectEffects 一般來源：角色→道具→連鎖→心願→夜規→異事；夜末 itemsFirst：道具→連鎖→角色→心願→夜規→異事。原 order 數值穩定排序仍保留。全域 hook 不收玩家連鎖。
- 毒標攔截位於扣款／得標計數之後、接收者 bag.push 之前。阻擋時既有 onWinItem 的 target 設 null（未塞入），不跳過得標方 hook；新增結果欄位只在阻擋時出現，無連鎖行為保持舊序列。
- 私有持有狀態不新增公開列表；銷毀的公開結果可指名水陸偷渡，承認可推知配方，不宣稱完全隱藏。

## 必過證據

1. 實作前新測試有效 RED 並提交；同一測試實作後 GREEN 並提交。上表所有路徑須以真實引擎或公開結果測試覆蓋。
2. CHAINS 空表時與基準 trace seeds 1–20 逐位元組相等；開啟後以規則測試驗證，不要求與舊規則相等。
3. 對攔截、命中統計／副作用至少兩種突變驗紅；新增查詢及攔截範圍覆蓋率 ≥80%，說明分母。
4. 受影響回顧、匯出、詛咒、hook 測試通過；必要瀏覽器結果開圖驗證，無 pageerror。全套既有 sfx-wiring seed3 停滯如再遇需保留失敗，不能稱全綠。
5. 獨立 JS／對抗式覆審無未解 HIGH／MEDIUM。
6. 正式發布仍受 L1 原六之四與 n≥10000 平衡閘門限制（追連鎖對 splitter −8～+5pp、持有者 +3～+10pp）。如舊工具不適用紙紮模式，先記缺口，不更換口徑假稱通過；實作可在隔離分支完成並驗證，不繞過發布條件。
