# 驗收條件凍結 — 妖市「盯上信譽」卷（2026-09-03）
基準 SHA：3137e42。動手前訂定，一經訂定即凍結（02 §2.1）。

## 使用者裁定（2026-09-03，五題）
1. 信譽**公開**，寫在角色卡 ⓘ
2. 視窗＝**只看最近 4 次**宣告
3. **拿掉虛張稅**（MARK_TAX → 0）
4. **現在就開**
5. 分數**按出價占行情的比例加權**（防「用便宜貨養信譽」）

## 設計
- 每個玩家（含 AI）有一份**全域公開**的信譽：宣告是公開的，全場看到同一份證據，
  所以不是「每個對手一份」——你不能對甲老實對乙騙。
- 每夜宣告結算後記一筆分數 `min(1, 跟進金額 / 該件行情)`；沒跟進＝0。行情＝`max(1, |it.p|)`。
- 信譽＝最近 4 筆的平均；**沒有任何紀錄時＝1.0**（沒騙過就該被信）。
- AI 的盯上反應乘上宣告者的信譽：
  怯場 `val -= Σcred × MARK_SCARE`；搶標 `val += MARK_CONTEST × (Σcred / 人數)`
  ——全員信譽＝1 時與舊算式**逐項相同**（這是 kill switch 能逐位元組相等的前提）。

## 驗收條件
Y1 **Kill switch**：`MARK_CRED_ON=false` 且 `MARK_TAX=1` 時，`trace(1..20)` 與 3137e42
   **逐位元組相等**——證明新機制是可關掉的疊加層，沒有順手改到別的東西
Y2 **開啟必不等**：`MARK_CRED_ON=true` 時 trace 與 3137e42 **不相等**（否則機制是死的）
Y3 **不耗新亂數**：Y1 相等即已涵蓋；另檢查記錄層與計算層零 `S.rng()` 呼叫（grep）
Y4 **活性**：一局 12 夜內，至少有一個玩家的信譽**離開過 1.0**，且分數不是只有 0/1 兩種值
   （＝加權真的在作用，不是退化成計數器）
Y5 **反漏洞（本卷的重點驗收）**：專門的探針模擬「用便宜貨養信譽」——
   連續盯最低價那件、只出 1 壽命跟進。**該打法的信譽必須明顯低於「盯主標並認真出價」的打法**
   （差距 ≥0.3，滿分 1.0）。做不到就代表加權沒效，要改實作不是改門檻
Y6 5 套測試全綠：8 / 5 / 16 / 28 / 36
Y7 **閘門 n=10000**：G1 原始軸與 G1′ 都跑，貼輸出。
   ★注意★：G1′ 是本輪之前才立的門檻，**本卷不得因為結果不好看而改動它的 P1/P2/P3**
   ——真的不過就如實回報，讓使用者裁定
Y8 UI：盯上宣告畫面看得到自己的信譽、角色卡 ⓘ 看得到該 AI 的信譽；
   844×390 四種夜型 `#felt` 溢出不大於基準；console 0 error
Y9 fresh-context read-back：新寫的規則說明，冷讀者要能複述「怎麼樣會掉信譽、掉了會怎樣」

## 不得做的事
- 不動 MARK_SCARE / MARK_CONTEST / MARK_OWN 的數值（本卷只加乘數，不調原係數）
- 不動其他角色的 aggr / spite / markReact
- 引擎函式內不得呼叫演出層或 `S.rng()` 以外的新亂數源
