# 《妖市》128 枚實體銅錢效能驗收（凍結）

使用者於 2026-09-14 裁定：保留最多 128 枚逐枚實體銅錢，並重新制定較高效能預算。
本檔在實作 128 枚量測前凍結；它取代舊上桌第二段 U3 對「32 枚」情境的三角形門檻，不降低原本的流暢度災難線。

## 真實壓力情境

- 以產品自己的 `tray.props.bid(seat, slot, 8)` 逐格推幣。
- 四席 × 四件拍品 × 每格八枚，合計 **128 枚**；不是直接改 InstancedMesh 的 count。
- 第 1 夜出價畫面、四件托盤拍品均已載入；四格逐一 hover，取三角形最多的一格。
- 同一支未封頂瀏覽器交錯量 `tray3d=0`／預設／`table3d=lite` 各五次。

## 放行條件

| 條件 | 門檻 |
|---|---:|
| 場上銅錢 | 恆為 128、`dropped=0` |
| 最壞 hover draw calls / frame | ≤ 140 |
| 最壞 hover triangles / frame | ≤ 42,000 |
| 最壞 hover render passes / frame | = 1 |
| 預設最壞 hover 每一次配對 renders/s 比值 | ≥ 0.40 |
| 三個變體的 console / page error | 0 |

## 門檻依據

初版量測使用每枚 96 triangles 的 12 段圓周；完整驗收出現一筆 render-rate 0.348，故在不減少枚數、方孔、厚度或材質層次下，將遠距離不可辨的圓周細分改為 8 段（64 triangles／枚）。128 枚因此較初版少 4,096 triangles。42,000 是可容納 128 枚、仍保有約 3,400 triangles 餘量的新上限。draw call 維持幾乎不變，因為 128 枚由一顆 InstancedMesh 繪製。0.40 流暢度比值是原本較嚴格的災難線，沒有下調。
