# 驗收條件凍結：今夜市集規則 3 條（NIGHTRULES）

## 使用者裁定（都照建議）
1. 沒有試玩回饋要先修，直接做市集規則。
2. 排程仿異事：`CFG.RULE_ON` 總開關、`CFG.RULE_NIGHTS=[3,7]`（避開異事夜 4/8/11、避開第 1 夜與末夜）、
   每局從 3 條抽 `RULE_NIGHTS.length` 條並洗牌配夜、前一夜夜末「夜市耳語」預告（與異事同欄）。
3. 落魄夜：保守標與押命標落標皆付 100%（覆寫 CONS_LOSE_FRAC 與押命標減半），掛號費照收，
   陰間當鋪典當例外照舊（仍只付掛號費），MAX_BIDS 不變。
4. 收祟夜：四件全從 CURSES 抽；買下銷毀本夜禁用（玩家 UI 與 AI 防禦性銷毀皆禁）；
   「流標」＝夜末沒有任何毒標得標的詛咒品，強制塞給當前壽命最高者（同分→依本夜風位起算的座位順序第一位），
   下手者＝無（不觸發紅衣婆婆記仇、不算 typeLeak）。
5. 押寶夜：每人只提交一個金額 X（型態可選保守／押命，X 受該型態上限約束）＋勾選要競標的法寶（非詛咒品，勾選數不受 MAX_BIDS 限制），
   X 對每件勾選拍品都視為出價 X，但最多得一件（依開標順序第一件得標即付 X＋掛號費並自動退出其餘）；
   全落標則依型態付一次落標費；掛號費只收一次。詛咒品本夜不開標（直接流標、不入任何人袋、無人可毒標）。

## 驗收條件（一經凍結不得移動；改實作不改條件）
A1 開關等價（雙向）：`CFG.RULE_ON=false` 時，新版與 `git show 5c8604d:index.html` 用**同一支現行 `trace()`** 跑 seed 1..20 逐位元組相等；`RULE_ON=true` 時必不相等（且 rng 消耗只在 true 時發生）。
A2 三規則各至少一條**行為斷言**單元測試，在 `5c8604d` 舊版上跑**恰紅在行為斷言**（不得因 undefined／TypeError 而紅；測試要透過 CFG 覆寫與可觀察效果驗，不得直接讀 NIGHTRULES 表），新版全綠。至少含：
   - 落魄夜：保守標落標付 100%；押命標落標付 100%；陰間當鋪典當在落魄夜仍只付掛號費。
   - 收祟夜：市集四件皆為詛咒品；無人毒標的詛咒品夜末進了壽命最高者的袋；該夜 AI 不出銷毀標、玩家 UI 無銷毀選項。
   - 押寶夜：勾選 3 件、X 在其中 2 件都是最高價 → 只得第一件、實付 X＋1 筆掛號費；全落標付一次落標費。
A3 三條迴圈共用同一套引擎：正常頁 UI、`simulate()`、`playPolicyGame()` 三者在規則夜行為一致（headless 把策略的多筆出價轉成押寶夜格式的規則要寫在引擎、策略碼不動）。
A4 活性：n=2000（RULE_ON=true）統計中，三條規則各至少觸發 1 次；收祟夜「強制塞給壽命最高者」至少發生 1 次；押寶夜「同一人 X 在 ≥2 件最高但只得 1 件」至少發生 1 次。
A5 平衡：同一版本 RULE_ON true/false 各 n=2000，splitter／greedy／hoarder 三策略勝率位移各 ≤1.5pp。超過就回報數字，不得自調 CFG 讓它過。

## 修訂（2026-09-02，使用者針對 A5 明確裁定「丁」；02 §2.1 程序）
**原標準錯在哪**：裁定 4 的收祟夜口徑「流標詛咒品塞給當前壽命最高者」讓「不出手」零成本——棄權者不付買路錢、不付毒標，流標詛咒品多半落在別人頭上；對真人而言棄權支配出手（同型缺陷＝異事第二批「零互動必有支配解」）。
**為什麼現在才知道**：A5 實測位移 +3.10／+3.75pp 後做治具實驗（`nr/a5-fixture.mjs`，n=2000）：策略改「棄權」位移與原樣逐值相同、改「毒標 1 點」仍 +1.80／+2.55 且勝率低於棄權——證明不是量測治具問題，是規格的支配解。
**修訂內容（裁定 4′）**：流標詛咒品塞給「本夜未出手者（沒有任何毒標進入結算）中壽命最高者」；全員皆出手時才落回「全體壽命最高者」；同分皆依本夜風位起算座位序。其餘（禁銷毀、下手者無、不觸發記仇）不變。
**連動**：A2 收祟夜斷言改為「未出手者中壽命最高者收到；同夜有出手且壽命更高者不收到」，並對修前副本必須恰紅在行為斷言。**A5 門檻 ≤1.5pp 不變**；HIGH-2 修法（AI keep→poison）已使 AI 出手率改變，A5 以修後版本重量。
