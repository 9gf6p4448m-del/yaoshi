## 1. 遮擋上限（拍品主體不被令牌擋住）
- 條件（A 口徑＝被令牌擋掉的拍品可見像素 ÷ 該拍品無令牌時可見像素）：
  - 單家盯（令牌落定後）≤ 1.5%。
  - 三家同盯同一件 ≤ 10%。
  - 視窗 844x390 與 932x430 各自成立；槽位 slot0 與 slot1 各自成立（含多人疊放最壞槽）；三家同盯在 slot0、slot1 都要實量（示意只量 slot1）。
  - 手拍令牌的拍擊瞬間幀（示意 s3a，單家 3.3%）：**門檻待裁**（裁點 1）；裁定前不得拿落定幀的 ≤1.5% 當它過關。
- 量法：沿用示意 `_mm.mjs` 的 measure()：同一場景分兩次離屏渲染——只畫該槽拍品（紅）與拍品＋令牌（藍疊上），取「拍品像素被令牌蓋掉」的比值。實作者須把 `_mm.mjs` 的 measure 提煉成入庫工具（建議 `tests/tools/mark-occlusion.mjs`），並先證明**工具等價**：在示意 C 變體上重現 844x390 s2＝7.9%（±0.3 個百分點）、932x430 s2＝7.9%（±0.3）、s1a／s1b＝0%，重現不了不得用此工具驗收。同時輸出 B 口徑（凸包相交）作參考，B 口徑不設門檻但須貼出。
- 紅：令牌往拍品中心再挪一點（遮擋 >10%）；疊放堆太高或太寬；令牌放大；只在 slot1 調好、slot0（外盤 edge 位移，`table-props.js` layoutTokens 的 edge 分支）仍超標。
- 鑑別力：對 5c91bdc7 現況量得 0%（健康狀態會綠）；對示意 C 的 s2（7.9%）會綠；把令牌往拍品方向平移 +0.15 m 必須紅（突變驗紅，實跑貼出）。示意 C 三家 7.9% 離 10% 只剩 2.1 個百分點，工具雜訊（像素取整、重跑差）須在凍結前量：同場景重跑 5 次的最大差。

## 2. 席位辨識（疊放時三枚令牌的席位色互相可分）
- 條件：
  - (a) 三枚疊放時，任兩枚的席位色在螢幕上的 CIEDE2000 ΔE ≥ T1。
  - (b) 每枚的席位色邊／底片與玉牌本體色（令牌本體未著色區）的 ΔE ≥ T2（對治「席位色乘在深色玉牌上辨識度低」這個已知問題）。
  - 視窗 844x390 與 932x430，slot0 與 slot1，三家同盯與單家各量。
- 量法：入庫工具（建議 `tests/tools/mark-seat-color.mjs`）——離屏渲染，每枚令牌的色邊／色底片以「席位專屬 mask 色」取得像素集合（避免和鄰枚混），再回到正常渲染取這些像素在最終畫面（含燈光、色調映射）的平均 sRGB，轉 Lab 後算兩兩 ΔE2000。
- **門檻怎麼訂（不得憑空）**：實作動手前，在示意 C 變體**加上色底片或色邊的最小補丁後**（示意目前只有 instanceColor 乘色，沒有底片）量一次兩兩最小 ΔE（記 m1）與色邊對玉牌 ΔE（記 m2），貼進本檔。T1＝⌊0.8×m1⌋、T2＝⌊0.8×m2⌋（0.8 是留給實作調整的餘裕），但 T1 不得低於 10、T2 不得低於 8（**10／8 是本檔作者的建議值，依據是 ΔE2000 約 2.3 為剛可察覺、10 以上一般視為不同色，需審者認可**，裁點 2）。若示意量不到 10，表示色票本身要換，而不是降門檻。
- 參考（未驗證）：標稱色 ffd23c／ff9ab0／5aa8ff／4cff7a 的標稱兩兩 ΔE 尚未算，進光後實際值只會更低——這正是要量的。
- 紅：色票只乘在深色本體上（示意現狀，T2 預期紅）；兩席色太近；疊放時上方令牌把下方令牌的色邊整個蓋住（該枚可見色邊像素 <N，N 須在凍結前依示意量到的像素數訂，建議 ≥ 該枚色邊總像素 50%）；單家看起來可以、三家疊放不可分。
- 鑑別力：對 5c91bdc7 現況跑一次（現況四席同色 tokenBase，兩兩 ΔE＝0，必須紅）；對突變「四席全用同一色」必須紅；健康側：示意加底片後必須綠。

## 5. 退回旗標 `?mark=0`
- 條件：`?mark=0` ＝ 令牌落點、尺寸、朝向、著色、接觸陰影、疊放全部與 v0.65.0 相同；預設（無參數）＝丙。旗標名沿用既有慣例（`?handreal=0`、`?fx=0`、`?cam=0`），改名須審者認可（裁點 6）。
- 量法（缺一不可）：
  a. **確定性等價**：同種子、同事件序列（1～3 家盯、slot0～3），`?mark=0` 與 v0.65.0 樹逐幀記錄令牌 InstancedMesh 的 `instanceMatrix`、`instanceColor`、`count`、接觸陰影 matrices、rack matrices，最大差 ≤ 1e-9。
  b. **像素等價**：同凍結幀三畫面（牌桌 1280×720、844×390、932×430），`?mark=0` 對 v0.65.0 的像素差 ≤ 同一棵 v0.65.0 樹重跑 ≥4 次兩兩差異的最大值（沿用 light-aplus 修訂 3 的雜訊底線做法，數字凍結前須量）。
  c. 組合矩陣：`?mark=0` × `?handreal=0/1` × `?fx=0/1`（8 格）各做 a。
- 紅：`?mark=0` 仍用新落點／新色；旗標只關其中一項（如關了落點、色底片仍在）；預設也關（預設測試紅）；旗標判斷寫成恆真。
- 突變驗紅：把旗標判斷改成恆真（及恆假各一次），a 與 b 都必須紅，實跑貼出紅燈。

## 7. 效能（不新增 draw call 超過 X）
- 做法照 light-aplus／camera-bid-curse 凍結檔：門檻對產品同幀量，不抄示意圖；iPhone 真機未量，不得宣稱。
- 量法：`tests/tools/light-aplus-perf.mjs` 同法（關 vsync、DPR 1、解凍後等 0.8s 再量 2.5s、每案一頁）。基準＝5c91bdc7 重跑 5 次；新版 ≥5 次取中位數，與基準中位數＋雜訊底線（5 次基準兩兩最大差）比。場景：既有 `bid`、`reveal`（基準數字見 camera-bid-curse 凍結檔：bid dcMed 84、dcMax 147、陰影重畫 ≤18；reveal dcMed 83、dcMax 141、陰影重畫 5）＋**新增場景 `mark`（盯上階段，三家同盯一件）**，其基準須在 5c91bdc7 以同一驅動重量（凍結前須量，目前無數字）。
- 條件：X＝**新增 draw call ≤ 2**（建議值：色底片與疊放併入既有令牌 InstancedMesh 或至多再加 1 個 InstancedMesh；**2 是本檔作者建議，需審者認可**，裁點 3）；cpuMed ≤ 基準中位數＋雜訊底線；陰影重畫次數 ≤ 基準；場景靜止時令牌不每幀重寫 instanceMatrix（量「靜止幀 instanceMatrix 寫入次數＝0」）。
- 紅：每個令牌獨立 Mesh（draw call +4）；色邊用每幀重建材質／geometry（cpu 上升）；疊放動畫常駐更新；令牌 castShadow 使陰影重畫次數增加。
