## ⑦ 新陷阱（6 條，⑮–⑳，已同步寫進 `guoyin.json` 的 `_traps`）

⑮ **★ claims 釘住某部位必須存在，而派工又要「那一區的掛件全部拿掉」時——搬家，不要改 claims。** 本隻 `part_exists ghost_wisp` 與派工的「虛半掛件全部拿掉」直接對撞；解法是把三片 `ghost_wisp` 從 `VArmWrist／VChest／VSpine` 整組移到袍襬背面的 `Mist2`：虛半一件不留、`claims.json` 一字未動、`part_exists` 照樣綠。

⑯ **★★「袖」讀不出來的真因不是顏色，是長寬比＋袖口收法。** r16 六位 0/6，本卷六位 6/6。三件缺一不可：(a) 換**色相**（藍靛 `#3d4a72` → 暗桑紫 `#64464e`；HSV S 要壓在 0.50 以下才不吃 `saturation_area` 預算）(b) 袖管 profile 改全程等寬直筒、`t=0.80` 微張成寬口後在 `t=0.86` 急收成細桿讓手掌從寬口伸出，長寬比拉到 ~2.1 (c) 袖口套一圈**短胖圓柱 `curve`** 當織帶。**環狀的短胖圓柱才會被讀成「滾邊／織帶」；細長桿子會被讀成骨頭或脊椎**（同一份 `trim` 材質，形狀一換讀法就翻盤——A・B 兩位在同一張圖上同時寫出「袖口米色滾邊」與「肩上骨節狀突起」）。

⑰ **★ 要「下襬平直」就把袍襬 volume 的 end cap 由 `dome` 改 `ngon`（平切），下襬舌片縮短到不越過那條切線。** 舌片一長出去就重新變成「鋸齒垂片／腳／靴子」。副作用要記著：silmetrics 的 `leg_fraction` 由 0.075 跳到 0.438（它把直筒下半身算成腿），**haunt「無腿」的機械訊號自此失真，別再拿 `leg_fraction` 當 haunt 的證據**。

⑱ **★ 袍襬鏈掛在 `Waist` 上會整條歪向實半那側**（`Waist` 本身在 x=−0.068），正視看起來像「歪一邊的桶子／底座」。要把它帶回整隻中線**不能動 root**——`root_containment` 檢查的是根環有沒有埋在 host 管內，`MistRoot` 一往中線移根環就露出來直接 BLOCK；只能靠 `Mist1／Mist2／MistTip` 的 `side` 逐節把它「帶」回去，且 profile 的 `t=0` 半徑必須留得比 body 半徑小。另附：`proportion` 會擋鏈的相鄰兩節長度比 ~50:50（本隻 `Mist1→Mist2→MistTip` 曾被擋在 0.94），拉長袍襬時要順手把節奏調回 0.62–0.85。

⑲ **★ 大襟做成平板 `fin` 會在 hero 3/4 被讀成「斜插在背後的木板／槍托」**（讀者 C 原話）——平板法線朝 +Z、hero 相機在 +X+Z，看到的是它的**厚度邊**。改回細圓桿 `curve` 只把 `dir` 加大斜度即可。更根本的問題：**實半的正面配件在 hero 與 stage-lit 兩個取樣視角都落在掠射角**，同 redhat 不對稱的取樣限制族——④ 這一條在現行兩張取樣圖下先天吃虧。

⑳ **★★ 虛半愈像一件「獨立的衣服」，「半透明的那半身」就愈讀不出來。** 第 3 輪把虛半的手臂再往外甩 0.014，虛半立刻從「包在一側的半透明白殼」（C・D，③ 2/2）變成「白色斗篷／披風」（E・F，③ 0/2），F 甚至把整件半透明袍襬讀成「透明的圓柱形容器或罩子」。**虛半要貼著實半、輪廓與實半連成一個人的形狀**，一旦它自己長出可辨識的衣服結構（獨立的袖、肩），讀者就把它歸給「披掛物」而不是「這個人少掉的那一半」。另附 `_traps` ⑩ 的實例再現：改過 volume profile 之後，掛在它上面的每一片 `fin` 的 offset 半徑都要重算（袍襬 `t=1` 半徑 0.094→0.150 之後，六片舌片全部埋進袍面；縱褶 fin 也因 host 那節 t 值改變而 `part_attachment` BLOCK）。
