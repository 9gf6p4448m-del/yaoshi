# X 閘（六之四跨夜模型）新發布裁定提案

日期：2026-09-24。狀態：**待使用者裁定**。本文件只提出選項，不改產品、數值、測試門檻，也不改變 `sixOfFour=incomplete`、`releaseEligible=false`。依[續作計畫 X 退出條件](../../../plans/2026-09-23-destiny-next-steps.md)第 155 行：完整跨夜模型不可行時，須帶實際探針、縮減證明與殘餘風險請使用者另行裁定；裁定前只能停在候選分支。

## 1. 要你裁定的事

X 閘目前要求「六組普通鏈＋天命真版，在原 `solo` 四席、12 夜的完整有限擴展式賽局上，證明不存在支配策略，且 `freeLunch` 不成立」（[L1e 模型契約](../2026-09-21-l1e-formal/model-contract.md)）。這個要求**以現有方法算不出來**。請從 §4 的甲／乙／丙／丁四選一，替換或保留這條發布條件。

**這個裁定只處理 X，不會讓 v0.57.41 可以發布。** 其他未過的閘門不受影響，見 §6。

白話術語：**支配策略**＝不管對手怎麼出，選它都不會比較差的選項；存在這種選項就代表那個抉擇是假兩難。**freeLunch**＝全員選同一個選項時，每個人都淨賺，等於白送。**資訊集合**＝某席在那一刻合法看得到的全部歷史。**chance 分支**＝洗牌、抽籤這類隨機結果的每一種可能。

## 2. 原標準錯在哪、為什麼現在才知道

1. **原始閘門是逐事件、離散網格。** [GAME_DESIGN 六之四](../../GAME_DESIGN.md)（第 389 行起）是針對「異事」：窮舉所有玩家對**該事件**的選擇組合；密封出價類「在合理的離散金額網格上窮舉」，再檢查有沒有支配選項。工具 `analyzeEvent`（`index.html:7998`）也照這個設計，上限 2,000,000 組。
2. **L1 提案把它套到被動連鎖，但沒有定義網格。** [L1 水陸 README](../2026-09-21-l1-water/README.md) 第 28 行自承：延伸到被動連鎖時「尚未定義購買行動網格、局面全集及收益時距」。
3. **L1e 契約把空白補成「完整 12 夜賽局」。** 契約要求所有初始化、所有 chance、所有資訊集合、所有條件策略，而且不得預先選價位。這比原閘門嚴格好幾個數量級，當時沒有量過規模。
4. **2026-09-23 的探針才第一次量出規模。** [可行性探針](model-feasibility-probe.md)：首夜、只算「每席恰選兩件非咒物的保守標」這個窄子集，四席聯合標單就已經是 `192 × 432 × 192 × 192 = 3,057,647,616`。這還不含空標、單標、押命、盯印、毒標、異事、香火，也還沒乘上後面 11 夜。`analyzeEvent` 的上限是 2×10⁶，差了三個數量級以上，而且這只是一夜的一個子集。

結論：錯的不是實作進度，而是**把逐事件閘門擴成全局賽局求解**這一步。這一步在沒有規模估計的情況下被寫成發布條件，直到探針出來才知道。

## 4. 選項

### 甲（建議）：回到原閘門口徑，做「逐鏈單夜子賽局」窮舉

- **內容**：對六組普通鏈和天命真版各自定義一個**單夜拍賣子賽局**：固定一組代表性局面（市場、袋子、生命），把各席動作放在事先凍結的離散網格上（例如：空標／保守標／押命 × 每件拍品 × 3–5 個金額級距）。收益由真引擎單夜結算得出，接的是 v3／v6 已驗證的 adapter。對每個子賽局跑支配策略檢查＋`freeLunch`，判準與 GAME_DESIGN 六之四完全相同。
- **可行性**：四席共用 ≤37 個選項時，`analyzeEvent` 原樣可跑（37⁴ ≈ 1.87×10⁶）。這個數字是推算，**還沒有實測**。
- **動手前要先凍結**：代表性局面的數量與挑選規則、網格、收益單位（當夜淨生命變化或終局勝率代理，二選一）、每組 pass 的定義。凍結後落檔，才開始跑。
- **殘餘風險**：抓不到**跨夜**的支配策略，例如「前幾夜故意不標、囤生命到後期掃貨」這類只在多夜才出現的策略；網格外的金額也可能藏支配解。這兩項照實寫進已知限制。
- **代價**：約一個工作階段做規格凍結，一個階段做實作加覆審。v2–v11 的 adapter 可直接重用。

### 乙：甲＋有限跨夜抽象

在甲之外，再加一個抽象後的 2–3 夜模型：只保留「生命、袋內連鎖進度、剩餘夜數」三個狀態，動作是粗網格，用反覆最佳回應（best-response）找有沒有穩定的支配路線。能補甲抓不到的跨夜囤積風險，但抽象本身要另證忠實度，而且結果屬近似、不是精確窮舉；**乙不是「更完整的甲」**，它多出來的跨夜部分，嚴謹度比甲低。代價約是甲的 2–3 倍。

### 丙：維持原要求（完整 12 夜模型）

X 繼續 `incomplete`，v0.57.41 以後的每個版本都會卡在這裡，除非出現新的求解方法。v2–v11 可以繼續逐節點補，但 §2 第 4 點的規模表示補完也不會自己變成 pass。

### 丁：X 改列非阻塞已知項

比照 2026-09-22 [選項甲](../2026-09-21-l1e-formal/README.md)對 H9 的處理，把 X 記為已知限制，發布只看 H1／H9 萬局與其他閘門。**要注意：** v0.57.37（三鏈）是在 `sixOfFour=incomplete` 的情況下發布的；`origin/main` 目前的 `2eb164d`（v0.57.40，六組普通鏈）也是在同樣狀態下合入的。當時的選項甲只明文裁了 H9，沒有明文豁免 X，所以實際上 X 已經至少被繞過一次。選丁等於把這個既成事實寫成明文。**實質後果**：連鎖將完全沒有任何支配策略檢查，只剩 H1／H9 的固定 AI 勝率；固定 AI 找不到的假兩難，上線前不會被發現。

## 5. 建議理由

建議甲。它就是 GAME_DESIGN 當初訂閘門時的原意（逐事件、離散網格、可機械判定），不是降標：跟目前的「沒有任何窮舉結果」相比，甲會真正跑出支配策略檢查，而且對六組普通鏈加上天命真版都有效。丁雖然最快，但連局部檢查都不做。丙在現有方法下等於永久卡住。乙可以等甲的結果出來之後再決定要不要加。
