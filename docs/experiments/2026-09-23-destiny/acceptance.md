# 天命密函與六組連鎖：施工前驗收契約 v0.2

日期：2026-09-23。基準：`2eb164d`／v0.57.40。來源：[原始 R1–R4](../../../.agents/ORIGINAL_REQUEST.md)、[接手 Premortem](../../reviews/2026-09-23-destiny-premortem.md)、[原 L1 放行閘](../2026-09-21-l1-water/acceptance.md)、[L1e 正式量測口徑](../2026-09-21-l1e-formal/acceptance.md)。本檔在任何天命數值實作、正式量測前寫定，並經獨立對抗覆審後補齊時序與來源語意；**原 R2 是產品基準，六組削峰只作實驗候選，尚未證明或獲准取代原案**。不追溯修改舊驗收和失敗 raw。A 的臂配置、受益門檻與規則邊界已凍結；M 的 runner 與正式數據仍未完成。

## 1. 既定產品規則及事件邊界

1. `makeState` 四席各抽六鏈之一，**有放回、彼此獨立**。命函使用與公開 32-bit 局種子無關的安全亂數逐席抽取，不增減原市場／夜規／戰鬥的 RNG 呼叫；同一 `(局種子, 四封私有抽籤結果)` 可重現。`p.destiny` 為自己可見的鏈 ID，`destinyAwakened` 初始為 `false`。普通六鏈仍照現有 `CHAINS` 規則向所有人開放。此處修正 v0.1 的「僅同種子重現」：獨立覆審可從公開首夜市場與角色枚舉回局種子，若私函也由該種子衍生，遮蔽公開回放 seed 仍無法保密；原 R1 保密優先，**公開 seed 保留市場重播能力**，私有抽籤結果只進內部量測輸入，不進公開回放。一般遊戲同種子跨重載重用私函仰賴本機儲存；若儲存受阻，僅同頁有效，正式量測必用明確私有抽籤輸入。
2. 一席在**拍賣實際入袋**後首次持有指定鏈的兩種非詛咒 `ab`，當場一次性覺醒；同名副本不重複觸發，先集齊非指定鏈只開普通效果。覺醒後即使材料離袋也不取消已公開身分，真效果則須仍滿足該鏈配方才有效，避免失去來源仍享永久免費能力。這個「身分永久／效果需持有」解讀列為 R1 實作契約，必以離袋反例測。
3. 覺醒前，該席私有袋子可見名稱與配方，其他席只能見未揭占位；拍賣公告、熱座交棒、公開回放和匯出都不得包含未揭鏈 ID 或能反推出它的私有欄位。覺醒後只公開當刻覺醒結果，不回溯公開未揭時的私函。此為**單機 UI／資料投影保密**，不宣稱用戶端 JS 有伺服器級防作弊。
4. 普通版仍依[整側存活的既有裁定](../2026-09-07-acceptance-duel-desync.md)運作，B 不改夜戰判定。**原 R2 未指定「施術隊仍活」新前提**：原案真水加血只跟隨現行成功抓交替，真長明盾只跟隨現行 `pwFeed` 成功；即使來源隊已死但整側仍活，原案照現有事件語意。來源隊限制僅屬 Premortem 候選，須與原案單獨量測，不藉此重寫普通版。
5. R3 是硬邊界：椅仔姑不得看對手生命；黃色小雨衣已有效的免押命本金效果不得被血祭改寫；千眼折讓實付至少 1；水陸補貼僅一夜有效投標且零得標時至多 1；所有新增 `t.tr`／`foe` 路徑安全；不使普通或真版戰鬥多出第四拍。200–300ms 指短版快拍路徑，不能拿生命損失 `PW_MIN/PW_MAX` 或三拍回合數冒充畫面時長。

### 原案實作前的確定性解讀

- 成本順序：`resolveAuction` 形成有效標與勝者 → 單注押寶夜只在得標件或最後勾選件計一筆費 → 落魄夜的全付規則優先於血祭 35% → 其他押命／保守落標比例 → 盯印及水陸買路錢 → 得標千眼折讓且底限 1 → 角色／物件保命鉤子 → 實扣。UI 必與引擎同一試算口徑，遇未揭結果顯示**範圍或條件**，不能承諾一個必定值。
- 原案真虎的「此拍品」沿用普通虎的**盯上拍品**範圍：只要真虎席盯此件，其他席的保守標實際落標就改 35%，不要求虎席也出價；多位真虎不能疊比例。35% 是替換原 25%，不是累加。候選才另要求虎席有效出價。同一席同夜水陸補貼只發一次，在拍賣結算後、死亡／出局掃描前核對 `bidAny` 和 `wonAny`。單注押寶夜的退出投標不算「有效落標」。
- 千眼四件是**逐席真實看見的預告清單**，不改所有人的 `S.prevPreview` 共同陣列；得標折讓只按自己的快照。神王「當夜」指請下尊的那一夜夜末 `settleTithe`，後夜照付；一人一尊既有門檻不變。長明最低壽命以當夜拍賣全部實扣之後、回血之前的四席生命快照判定；原案並列最低者都符合，候選才改風位單席。
- 各真效果只在明定的拍觸發或建立狀態；持續期間依下方 D/E 裁定（雙虎整場、長明盾至耗盡或場終），不得一律限單拍；來源多份時同鏈附加效果預設一戰一次，避免同一配方或一件重複物品倍增。既有普通效果按原引擎可重複的部分不由天命調整。若這個防重規則與 R2 字面「每拍」衝突，以每拍一次為上限，不縮成全戰一次。
- AI 在生命 `>=18` 時，只有**新增該席指定天命所缺的材料**才另加估值 2；已持有同 `ab` 的副本、對手私函或非指定鏈不加。這是普通連鎖既有 `aiBonus` 之外的真版追件加權；生命 <18 停損，不停止 AI 的正常標價。

### D/E 實作前的時間與護盾裁定

- 真雙虎在每場開戰登場時只選一次敵方**當下首位存活前鋒**，該單位攻擊力 −1 並持續本場其餘三拍；「永久」只指這場戰鬥，不跨下一場，不隨目標死亡轉移至次位。原案與候選同樣維持此期間；候選的「每戰一次」只是防止多份來源重施，不縮短持續時間。
- 真長明原案在每次實際成功的拍末 `pwFeed` 後，選本方當下血量最低的存活單位（同血依引擎隊伍／單位順序），給該單位 2 點**個人吸收額度**；同場後續成功進食可再加 2，直到該單位受傷耗盡或本場結束，不跨新對決。傷害先走既有送王船的全方共用吸收，再耗此個人額度，最後才算護甲；陰陽眼僅穿透送王船，不穿透新盾。原案維持既有整側存活的進食語意，重複甕不因同拍重複發盾。候選才增加來源隊存活、個人額度上限 2，且若下一拍未耗盡則在該拍結束後消失。第 3 拍新生盾因沒有第 4 拍，只記觸發、不給戰果效益；測試不得把第 3 拍盾當成勝率加成。
- 真長明「全場最低額外 +1」在**整夜拍品實付全部完成後、拍賣出局掃描之前**核對四席生命快照並發放；因此可把當夜剛降至 0 的席救回 1，但不能復活拍賣前已出局者。原案並列最低皆領，候選才以風位定單席；兩臂發放時點相同。普通版既有 `onNightEnd` 添油 +1 仍在夜末執行，不提前。
- 已覺醒但指定材料離袋時，自己的袋子必須顯示「已覺醒・缺材料，真效果暫停」，相關出價提示亦須依引擎的真效果 active 判定；對手不因這行提示取得私有袋中資訊。補回材料後恢復效果而不再廣播第二次覺醒。

## 4. 數值實驗與判定，跑正式資料前不得更改

機器可讀臂見 [arms.json](arms.json)。每臂先跑 seeds `10001..20000` 共 10000 局；固定以每 10000 種子遞增至最多 `110000`，**僅因普通基準臂的事前覺醒群未達每鏈 300 次而續跑**，不可按勝率／通過機率擴樣。這串未查明是否曾用在其他卷，**不稱盲驗**。每臂 fresh load，最多三個 Node 行程；報程式、runner、契約與配置 SHA256。先為每個 seed 建一份四席私有抽籤輸入，在 `scratchpad/` 等不公開目錄保存原表並記其 SHA256，六臂讀同一份 `(seed, 四封函)` 配對；驗證每列與原表一致，不把私有輸入寫進玩家公開回放或公開版本庫。沒有成型的局也留在全局分母。六組 H1 使用既定 splitter／`target-chaser-v1`／`eyes-informed-v1`；新三組依相同 `createChaser` 函式具名，不重調係數。H9 原桌用空 policies、預設四席 AI 與原角色抽樣。舊三鏈的 H1 `−8..+5pp`、原 H9 `+3..+10pp` 及千眼 H9 `incomplete` 保持[原口徑](../2026-09-21-l1e-formal/acceptance.md)，不能用新資料消除其歷史失敗。

真版使用**兩因子、六主臂**：`ordinary/original/candidate × AI 天命追件 off/on`。每個臂都抽相同四封命函、用相同普通連鎖、同一席位／角色／策略與其他 AI 規則；六臂一律開 `recordChainHoldings:true` 和 `policyInformation:true`，千眼策略須實際收到自己的三件／四件預告及合法第二高標資訊，記 `informedVsBlindDiff`，不能因 `ctx` 缺失退化成 blind。`ordinary-ai-on` **只**打開 AI 追件 +2、不打開真特權。`original-ai-on` 對 `ordinary-ai-on` 量「策略相同時開啟原案特權」；`ordinary-ai-on` 對 `ordinary-ai-off` 量追件 AI；`original-ai-on` 對 `ordinary-ai-off` 才是**整包產品效果**，不得叫真特權的純效果。候選同理。覺醒群要在完全未開真效果的同一相位與 RNG 狀態建立完整 checkpoint，再從這一點分流；**只切焦點席自己的指定真效果，其餘三席真效果在兩支都關閉，以焦點席終局勝負作指標**。若尚無可驗證的 state+RNG restore，只可報全局配對產品差，覺醒群因果判定固定 `incomplete`，不可用事後 holder 篩選替代。

百分點用 pp，95% 區間由**配對逐局差**按 seed 群集重抽樣（固定 10000 次、重抽樣種子 `20260923`、實際方法與每格分母寫入報告）而非獨立兩比例公式。舊 H9 的 holder 條件差不是因果；新規則不把它改名成因果。試跑只驗工具，正式臂不得依結果改策略、種子、係數或門檻；調值須新候選 ID、新 raw、新報告。機械門檻之外，早覺醒神王、雙虎敗標罰與長明拖局各有定向最差情境；任何可反覆利用漏洞或資訊洩漏均為 HIGH，不因平均勝率在帶內而放行。

## 5. 正式發布關口
