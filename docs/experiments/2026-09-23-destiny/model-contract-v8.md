## 本版新增的可證明範圍

`tests/tools/l1e-full-recall-adapter-v8.mjs` 先確認產品固定來源，再載入合併所需 API 的凍結引擎。事件、盯印、放血、拍賣及選尊 observation 只有在由各自 pinned adapter 實際產生後，才由模組私有 WeakMap 登記，並綁定其引擎及狀態根。符合 schema 且深度凍結的手造物件或複製物不會取得 provenance，因此不能加入回憶歷史；即使同一引擎實例，不同 state root 也不能拼接。盯印、放血與拍賣投影若帶有事件揭露，也必須引用 v8 產生的同引擎、同狀態公開轉移；呼叫者不能直接塞入仿造揭露。

v8 私下追蹤狀態版本。透過 v8 完成異事結算、盯印、放血、開始神龕解析或選尊後，先前 observation 不能再當成新決策或目前節點使用；目前 observation 也不能倒退到歷史末端之前。同一狀態根、相位、輪次、席位與狀態版本構成一個決策節點；即使另建決策物件或分支歷史，也不能記成互相衝突的動作。事件、盯印、放血和選尊的 v8 commit 會核對該節點的動作。事件結算與神龕解析也各限制同一狀態每輪執行一次。事件揭露還會再次核對該席實際公開選擇。版本只會在這些 v8 包裝點遞增；提交時也會拒絕版本已過期的決策，同一版本的動作只能消費一次。重複放血須重新建立決策並把新動作接入歷史。任意直接改動 state、拍賣提交及尚未建模的戰鬥／夜末／跨夜轉移不會自動更新版本或核對動作，因此這不是完整逐事件時間線。

異事結算回傳的公開揭露會被包成 `event.reveal` transition。此 transition 只能接在同席、同輪、同一決策物件的事件決策後，且該席歷史所記錄的密封選擇必須與引擎實際揭露相同；歷史鍵包含這筆公開結果，因此揭露前後資訊集合鍵不同。重複 transition、同一單次相位重複決策、跨席歷史、不同引擎來源、同輪錯序與倒退輪次都會被拒絕。放血可同輪重複，但不得重用同一決策物件。

歷史要往後推進時，異事決策必須先有同席公開揭露；盯印、放血與選尊的記錄必須先在該狀態節點實際提交。相同輪次的決策投影必須來自更後的狀態版本；另一個事件決策物件晚寫入歷史時，也要與該節點已提交的選擇一致。這些限制只涵蓋 v8 包裝器能追蹤的轉移，拍賣 action/state 與其他自動轉移仍未追蹤。

事件決策在建立時綁定同一狀態根、輪次與版本；同輪此事件階段不得在後續版本重開。觀察、提交與結算都拒絕過期事件決策，因此盯印等後續狀態變更不能讓舊事件延後結算或用新決策覆蓋待揭選擇。

這只證明五種既有決策投影與一種公開轉移的 adapter 邊界。私有 WeakMap 是本地測試模型的來源標記，不是伺服器安全或惡意同程序程式碼的隔離機制。

## 未完成範圍

- 尚未把拍賣公開揭標、戰鬥、夜末結算、死亡、神龕和跨夜市場／異事排程等所有決策間轉移接入序列。
- 尚未證明全遊戲每個隨機分枝與條件機率都完整，也沒有全席、全政策資訊集合等價證明。
- v2 的局部 snapshot 不等於跨夜 canonical restore；遊戲 RNG、UI RNG、公開歷史與私有天命的跨夜恢復尚未驗收。
- 終局效用、可行的策略枚舉／求解範圍與獨立求解器審查仍未定義或執行。
- 盯印時序配對診斷已完成，但只適用其固定 AI fixture，不能外推真人公平性或一般勝率相等。
