## 1. 改了什麼

### 1.1 斷手書生：`onAiValue` 取凍結檔範圍段的「改法二」

`index.html:961-964`（原 `index.html:943` 一行；註解在 `950-960`）。原式：

```js
onAiValue(ctx){ ctx.val*=(ctx.item.f===lockedSpec(ctx.p))?1.6:0.7; }
```

`1.6` 是專精識別度，但那個 **`0.7` 把市場上其餘七成的貨一律低估三成**——斷手因此連該搶的都搶不到。
量法卷 §7.2 量到這一包 AI hook 整體值 **−7.42pp**。改成：

```js
onAiValue(ctx){
  const spec=lockedSpec(ctx.p);
  if(ctx.item.f===spec && ctx.p.bag.filter(x=>!x.curse&&x.f===spec).length===3) ctx.val*=1.6;
}
```

＝**只對「能湊成套的那一件」加價**（袋中鎖定系恰好 3 件、這一件正好是門檻的第 4 件），其餘照原估值。
件數判準與下面 `onAiAmount` 的破戒條件寫成同一式，不另訂一份。

**為什麼取這個而不是改法一**（凍結檔要求「擇一、理由寫報告」）：先用 n=2000 探針各量一次
（其餘完全相同、只換這一個 hook，`--html=` 指向 scratch 變體，不動 repo）：

| 變體 | 斷手 (b) n=2000 | 對基準位移 |
|---|---|---|
| 基準 `5a3c56b` | 15.30% | — |
| 改法一（鎖定系 ×1.5、其餘不打折） | 15.95% | +0.65pp |
| **改法二（只加湊成套那一件）** | **18.40%** | **+3.10pp** |

n=2000 的 SE 約 ±0.8pp，兩者差 2.45pp ⇒ 差距在雜訊之外。證據：`…-b-evidence/probe/`。
**但這個 2.45pp 後來被 n=10000 打臉**：探針那格「基準 15.30%」偏低（n=10000 的真值是 **16.64%**），
把改法二的增益放大了。第二輪以 n=10000 正式量改法一是 **16.77%**、改法二是 17.34%，
**兩者只差 0.57pp、在 1.1 個 SE 內，並不顯著**（§3.2）。**選改法二的理由事後看只剩「方向一致、且不比較差」**，
不是「明顯較好」——這一點不含糊帶過。

### 1.2 紅衣婆婆：記仇的**讀取端**搬到玩家與 AI 共用的掛點

`index.html:885-888`（新增 `onBidEff`，註解 `877-884`）與 `index.html:919-920`（原 `onAiValue` 整條移除，只留一行沿革註解）。

診斷（量法卷 §7.1）：`grudge` 帳本的三支**寫入** hook（`onBidSettle` 被搶標 +1／`onBattle` 被擊敗 +1／
`onNightEnd` 每夜衰減）**玩家照跑**，但唯二的**讀取端**（`onAiCurse` 毒標鎖仇人、`onAiValue` 掐仇人主系 +3）
都在 `aiBids()` 裡——`onAi*` 真人玩家永遠吃不到（GUIDE §11.1）。所以玩家的記仇只進不出。

改法：把「掐仇人主力陣營 +3」整條從 `onAiValue` 搬到 `onBidEff`（`resolveAuction` 對每一張標書都跑，
玩家與 AI 同一條）：

```js
onBidEff(ctx){
  const t=topGrudge(ctx.p);
  if(t && mainFaction(t)===ctx.item.f) ctx.eff+=3;
}
```

**效果數值不變（+3）、只改觸發路徑**——凍結檔範圍段的要求。報告 §7 選項 C 乙原本提的是
`+min(4, grudge)`（隨仇恨值遞增），本卷**沒有採用**，因為那是新數值；用既有的 +3 常數。

**誠實的一句**：「數值不變」不等於「強度不變」。`onAiValue` 改的是 AI 心中的估值（它會真的多付壽命），
`onBidEff` 改的是比價 `eff`（**實付不變**，同青面攤主那條路）——後者對持有者更划算。
所以紅衣拿到的 +7.18pp 比報告 §7 估的 +2～+4pp 大，**這不是估錯，是搬家換了語意**。

`desc` 跟著改（語意變了）：`index.html:875`。`VERSION` 0.47→**0.50**：`index.html:1856`。

### 3.3 交互作用：紅衣的增益從斷手身上收走多少

診斷（不是驗收條件，是為了把「差 0.66pp 從哪來」講清楚）：只改斷手、紅衣不動，n=10000：

| 版本 | 斷手 (b) n=10000 |
|---|---|
| 改前＠`5a3c56b`（兩隻都沒改） | 16.64% |
| **只改斷手（改法二）、紅衣不動** | **17.85%（+1.21pp，離 18% 還差 0.15pp）** |
| 兩隻都改（現行） | 17.34%（對改前 +0.70pp） |

⇒ 兩件事拆開來看：

- **改法二自己值 +1.21pp**（16.64 → 17.85）。**即使紅衣完全不動，斷手也只到 17.85%、仍差 0.15pp**
  （在 SE ±0.38 內，等於「剛好壓線但沒過」）。
- **紅衣的改動再從斷手身上收走 0.51pp**（17.85 → 17.34）。這是本卷唯一一組**同一引擎、同一 n**
  的零和證據；§3.1 其餘八隻的位移是跨版本相減，混著斷手那一項，不能拿來當同樣強度的證據。

所以「斷手差 0.66pp」的來源是 **0.15pp 自己不夠 ＋ 0.51pp 被紅衣收走**。
**光把紅衣調回去救不了斷手**（頂多回到 17.85%）——這一點推翻了「調紅衣就好」的直覺，寫在 §8 選項 3。

## 8. 停手點與選項（斷手書生 17.34%，差 0.66pp——**請使用者裁**）

1. **接受 17.34%**。它比改前的 16.64% 高 0.70pp，是全表唯一還在帶外的一隻（0.66pp）；

   它是斷手「紀律：每夜只標一件」的識別度來源，動它會改角色手感（硬規則 3）。

3. **把紅衣的 `onBidEff` 從 +3 降到 +2**。⚠️ **§3.3 已經證明這條單獨做不夠**：紅衣只從斷手身上

   **要用就得和選項 2 或 4 搭配。**
4. **兩個改法合併**（鎖定系常態 ×1.5 ＋ 湊成套那件再 ×1.6）。凍結檔寫「擇一」，合併要另裁。

## 10. 沒做到的、假設過的

### 10.1 沒做到

1. **C1 沒有全部達標**：斷手書生 17.34%，差 0.66pp。兩輪額度依 C5 用完，選項在 §8，等使用者裁。
2. **其餘八隻的「改前」沒有在 `5a3c56b` 上重量**，沿用 v0.47 報告 §4 的數字（那份的八隻又是
   「門檻 2」那一輪量的，見該報告 §10.1 第 0 點）。所以 §3.1 的「位移」欄對這八隻是**跨版本相減**，
   只當方向與量級用。斷手與紅衣兩隻是本卷自己量的，位移可信。
3. **沒有真機試玩**。全部 headless 模擬＋一次 Playwright 演出檢查。紅衣的比價 +3 在真人手上
   會不會「感覺得到」，只有試玩才知道——它是被動、沒有任何 UI 提示。
4. **沒有量紅衣改動對「AI 紅衣」的影響**。搬家之後 AI 紅衣不再多付壽命（`onAiValue`）而是白拿比價
   （`onBidEff`），對手感的影響沒有單獨量，只知道合成結果是 +7pp。
5. **`onAiPlan` 的 `maxPicks` 一個字沒動**（凍結檔的「二選一」只給了兩個 `onAiValue` 改法）。
   量法卷點名的 −7.42pp 裡有多少屬於 `onAiPlan`，本卷沒有拆。

### 10.2 假設過

1. **`topGrudge()`／`mainFaction()` 在 `onBidEff` 裡呼叫不消耗亂數**——兩者都不走 `S.rng()`
   （`topGrudge` 的同分 tie-break 走 `power()`，`power()` 也不走 rng）。C3 的逐位元組相等就是這條的證據：
   如果它們動到亂數序，移除兩隻之後的 trace 不可能還相等。
2. **紅衣的 `onBidEff` 在「一注多押」與「退出注」的統計路徑上也會被呼叫**（`index.html:2515`／`2525`），
   後者是純統計、不影響結算；沿用青面 `onBidEff` 的既有語意，沒有另做例外。
3. **改法二的件數判準用 `ctx.p.bag.filter(...)` 而不是 `facCount()`**——與同一隻的 `onAiAmount`
   破戒條件寫成同一式（那一行本來就是這樣寫的）。兩者的差別是 `facCount()` 會跑 `onFacCount` hook
   （雷女之火：祖靈視為多 1 件）。**所以「AI 出價時認為自己湊得到第 4 件」與「被動實際生效」
   在帶雷女之火時會差一件**——這是沿用既有寫法造成的既有不一致，本卷沒有修（修它會動到 `onAiAmount`，
   超出範圍），寫在這裡不含糊帶過。
4. **凍結檔 C1 寫的改前基準（斷手 15.6／紅衣 16.3）與 v0.47 報告 §4 表格（16.63／16.26）對不上**。
   本卷實測 `5a3c56b`，以自己量到的為準（§3.1）。**沒有回頭去查 v0.47 那格 16.63 是怎麼來的。**
