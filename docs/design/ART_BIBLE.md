# 妖市陣營美術聖經（2026-09-04，使用者提案、主對話依引擎與遊戲調整）

> 權威文件。任何角色／法寶／演出的美術決策先查本檔；量產凍結檔 `docs/experiments/2026-09-04-acceptance-creature-batch.md` 的美術守則以本檔為準。
> 核心：**大作等級的陣營設計，差別不在細節多，而在三秒可辨識**——遠處、小圖、全黑剪影都要分得出是誰。每個陣營先定死四件事：剪影、單一主色、關鍵材質、動態節奏，再談造型。

## 0. 共通鐵則
1. **剪影測試**：全黑填滿仍能區分三系（詛咒品是「物」，另計）。每批合併後做一次機械盲讀（§6）。
2. **一色定調**：每陣營一個招牌色，其餘中性；引擎沒有貼圖，色只能靠 `colors.arcs` 分帶＋實體 `fin` 色條落在**一個部位**。
3. **材質即敘事，但我們沒有貼圖**：材質語言全部翻成**幾何＋頂點色**（§5 對照表）。
4. **最重要的對比**：陰氣是自然生成、無主的；詛咒是人為製造、有作者的。
5. **不可愛**（使用者 2026-09-04）：圓臉圓眼、短胖圓潤、微笑、Q 版、粉嫩色一律禁；精緻、大作感。
6. **體型 × 陣營**：體型（swarm／elite／haunt／ward）決定尺寸與隻數，陣營決定剪影文法；衝突時陣營文法在體型框內實現（例：祖靈 ward＝多根垂直圖騰柱排成一面寬牆）。

## 0.5 真實參照鐵則（使用者 2026-09-04：「祖靈、香火、陰氣都直接去真實參照實際的圖片或樣式去設計，百步蛇就要讓我一看是百步蛇的樣子」）
每隻在寫 JSON 之前**必須**先做參照：
1. 找 2–3 張**真實**參照（實物照片：動物、器物、神像、廟宇雕刻、民俗畫；優先 Wikimedia Commons 等可公開取得者），下載到 `tools/anyCreature/out/ref/<ab>/`，**親眼看過**（Read 圖檔），不得只讀文字描述。
2. 從照片抽出 **3–5 條一眼特徵**（例：百步蛇＝三角形大頭、吻端上翹、背部一列尖朝上的深褐三角斑、淺褐底色、粗短身），寫進 `docs/experiments/2026-09-04-ref-<ab>.md`；這幾條就是造型的必做清單，模型上每條都要看得到。
3. 盲讀加一問：「請列出你看到的特徵」——context-free 讀者列出的特徵須命中清單 ≥3 條；只讀成「蛇／獅／船」但特徵不合＝未過。
4. 圖騰化、風格化是**在特徵之上**做，不是取代特徵：祖靈的百步蛇菱紋可以做成琉璃珠，但蛇本身仍要是百步蛇。
5. 已完成的模型一律回頭用此鐵則檢視（回修檢視卷）。

## 1. 香火｜被記得才存在
存在的燃料是供奉；沒人上香就衰弱。
- **主色**：硃紅（`--c-xianghu #c84040`／亮 `#f08060`）＋鎏金（`--c-gold`）＋香灰白（中性）
- **材質語言**：上漆木雕、剪黏碎瓷、交趾陶、金箔、絹旗、積年香灰
- **剪影**：寬、正、儀仗感；靠**垂墜物**（令旗、鈴、瓔珞、綬帶）製造輪廓。側視 W/H 目標 ≥ 0.9
- **節奏**：緩慢、有拍子，像抬轎——idle 2.4–3.0s 對稱擺、attack 先蓄後落
- **避開**：中國宮廷龍袍；台灣廟宇是「濃、艷、密」的民間華麗
- **不用**：殘缺、腐爛、空洞眼

## 2. 祖靈｜被繼承，不是被供奉
力量來自血脈與土地的契約；香火要人拜，祖靈只認人是誰。
- **主色**：大地褐（`--c-zuli #8b6040`／亮 `#d4a870`）＋**靛藍**（新增次色，用於琉璃珠、眼、織紋帶，emissive 可用 `#3050a0`）＋少量赤紅
- **材質語言**：手織麻、風化木、獸骨、皮革、藤編、琉璃珠
- **剪影**：修長、**垂直線條主導**（祖靈柱、羽飾、長矛、角）。側視 W/H 目標 ≤ 0.7（swarm 例外：橫排體型改以「每隻帶一根垂直物」達成）
- **節奏**：靜時如樹，動時瞬發——idle 近乎靜止（幅度 ≤ 香火一半）、attack 0.4–0.5s 爆發
- **文化提醒**：織紋、聖物**抽象化與虛構化**，不混族群、不挪用禁忌實物；上市前找族群顧問（使用者裁定）
- **不用**：腐朽、裂嘴、空洞眼

## 3. 陰氣｜沒被安置的東西
台灣鬼怪的恐怖是「日常裡的錯位」，不是歐美惡魔的猙獰；可怕的是它們太像人。
- **主色**：苔綠（`--c-yinqi #3d6e4e`／亮 `#70b080`）＋濕黑＋**一點刺眼的紅或白**（IP 色：紅帽、黃雨衣在此例外放寬）
- **材質語言**：吸飽水的布、霉斑、濕髮、泥、榕樹氣根
- **剪影**：**不對稱、比例錯誤**（手太長、頭太低、關節多一節）；haunt 下半身虛化
- **節奏**：卡頓、不連續、拍子錯開——idle 用 hold＋突跳的關鍵影格，attack 前有一拍靜止
- **關鍵**：讓玩家先覺得「好像是人」再覺得不對
- **手段全開**：空洞眼、裂嘴、細長指、骨感、殘缺

## 4. 詛咒｜有作者的惡意
不是靈，是**物**；每件都是某人親手做來害人的。目前是法寶／毒標的道具語言（卡面、毒標演出、詛咒纏身狀態），不是戰鬥單位。
- **主色**：墨黑＋血褐＋泛黃紙色（UI 現用紫 `--c-curse #6040a0` 留作介面辨識色，道具本體改走本段；日後統一另裁）
- **材質語言**：舊符紙、鏽釘、封蠟、繩結、頭髮指甲、陶罐
- **剪影**：體積最小、密度最高；綑綁、被封住
- **節奏**：靜止但在呼吸，被觸發才爆發
- **關鍵**：看得出製作痕跡——歪掉的字、綁太多圈的繩、封了又封的口

## 5. 材質語言 → anyCreature 幾何／頂點色 對照
| 語言 | 做法 |
|---|---|
| 剪黏碎瓷、交趾陶 | 多片小 `fin` 以不同色塊拼在肩胸；`colors.arcs` 窄帶交錯 |
| 金箔、鎏金 | `--c-gold` 色塊集中在一件配件（印、牌、劍脊）＋`glow_*` emissive |
| 絹旗、綬帶、瓔珞 | 垂墜 `fin`（凸多邊形、內緣埋進宿主），動畫給滯後擺動 |
| 香灰 | 肩頂一層灰白 arc 帶（不發光） |
| 獸骨、獠牙、角 | `spike`／薄 `fin`，骨白色，尖端外露 |
| 藤編、織紋 | `colors.arcs` 規律窄帶（2–3 色交替）；不做寫實圖騰 |
| 琉璃珠 | 一串小球 `eye`／`curve` 節點，靛藍 emissive |
| 濕布、濕髮 | 下垂 `fin` 條、profile 不對稱、`ghost_*` 半透明在末端 |
| 霉斑、泥 | `shading.noise` 開大＋深綠黑 arcs 不規則帶 |
| 氣根、水草 | 多條細 `curve` 從腰以下垂落，長短不一 |
| 符紙、繩結（詛咒） | 卡面用 2D；3D 演出時用小方 `fin`＋紅細 `curve` 綑綁 |

## 6. 剪影三秒測試（批次閘門，每兩批做一次）
把已完成的所有生物側視 mask 全黑縮成 48px，隨機排成一張拼圖，派 **context-free** 子 agent 分成三組（不給陣營名，只說「分成三類」）；再對照真實陣營算純度。門檻：**每系純度 ≥ 2/3**。未過的那一系，該批新做的先改剪影再繼續。這條是本檔新增的閘門，凍結後不動。
> **2026-09-05 修訂（使用者裁定，見量產凍結檔 09-05「主色剪影」段）**：全黑 mask 兩次實測只量到骨架拓樸，測法改為**主色剪影**（mask 以各隻聖經主色填滿再分三類）；其餘門檻不變。
> **2026-09-05 再修訂（使用者裁定）**：主色剪影亦零鑑別力（第 3 次），本節**降為監測項**：每兩批記錄純度與分類軸，不擋批；陣營辨識由後處理卷（描邊／邊光）承擔。

## 7. 低多邊形切換
我們就是低多邊形（anyCreature、頂點色、無貼圖）。剪影、主色、材質語言在低多邊形下**更重要**——那是僅剩的辨識手段。所有設計簡報以本檔的四件事開頭，再談造型。

## 8. 燈光與色調（2026-09-07 美術甲「夜市燈火」卷加入；常數在 `js/scene-env.js` 的 `ENV`／`LANTERNS`）

這一節管的是**場景**，不是生物；生物的材質語言仍看 §5。與 §0.5「真實參照鐵則」一致：色溫與擺位取自
真實廟埕夜市（燭火、燈籠、香爐、路口路燈），不做卡通化的彩色打光。

| 項目 | 值 | 理由（改之前先讀這欄） |
|------|----|------|
| 色調映射 | `ACESFilmicToneMapping`、`toneMappingExposure = ENV.EXPOSURE`（1.1） | 全域，牌桌／市集也吃得到。three 的 ACES 內部另乘 `exposure/0.6`，所以 1.1 已經是明顯提亮；27 隻妖 lookdev 發白時**調這個數字**，不是調驗收門檻 |
| 輸出色彩空間 | `SRGBColorSpace`（明寫） | 不吃預設值，避免升 three 版時靜默改變 |
| 後製合成 | 不得在 `js/bloom.js` 手刻色調映射 | 手刻＝兩條路（直接 render／bloom）各走一條曲線，牌桌與對決的同一盞燈會是兩個顏色。合成那一趟用 `ShaderMaterial` 讓 three 注入 `tonemapping_fragment`／`colorspace_fragment` |
| 四盞燈籠 | 東 青白 `#d8e8ff` 3.2／南 橘 `#ffa855` 4.6／西 琥珀 `#ffc070` 3.8／北 暗紅 `#a8402a` 2.6 | **四面不得同色同亮**——同色溫等亮＝沒有明暗交界，桌子會像攝影棚裡的道具。南（玩家）最亮、北最暗，桌面因此有一條可辨的明暗界線 |
| 補光 | `HemisphereLight`（天 `#5a5484`／地 `#7a4a22`，1.2）＋ `AmbientLight` `#2a1840` 0.35 | 暗部不死黑、且帶一點藍紫；與燈籠的暖光形成冷暖對比。**不要只放一顆 AmbientLight** |
| 夜空 | 漸層穹頂（`SKY_STOPS` 五站：近黑→夜紫→水平線暖紫紅→藍紫→天頂更暗） | 背景不得是純色。牌桌機位是俯視（畫面最上緣＝水平線下 8.7°），所以**看得到的那一段是水平線以下**——亮圈與夜紫的位置是為這件事排的，改機位要重排 |
| 霧 | `FogExp2`，顏色＝`ENV.SKY_FOG`（牌桌看得到的那一段夜紫） | 遠處要化進「畫面上真的看得到的那個顏色」，不是化進純黑 |
| 遠景剪影 | 5 片 `far-*`，距離 8.5～9（程序化幾何＋頂點色，**不載外部貼圖**） | 俯視使離地 0.85 世界單位以上的東西會跑出畫面，所以剪影縱向壓扁 0.26～0.34；暖色燈籠點要放在離地 0.5 以下才看得到。對決時整組淡出——對決機位下剪影底邊落在 NDC y 0.28～0.53，而人形佔 NDC y −0.53～0.75，**剪影整段都落在人形範圍之內**，靠擺位閃不開（要閃開得把剪影推到約 489 單位外） |
| 暈角 | CSS 覆蓋層 `#vignette`（canvas z-index −2、暈角 −1、UI 在上） | 不進 shader：手機上多一趟全畫面 fill 太貴 |

**陰影**：全程不開（手機）。要開之前先在 iPhone 量到 fps 才談。

## 9. 傳說三尊（2026-09-07 美術卷）

三尊不在 27 隻的 POOL 裡，走 `LEGENDS`（`index.html`），但**美術守則完全比照 §0–§7**：一色定調、材質語言翻成幾何、不可愛、真實參照鐵則。造型守則各一句：

| 尊 | 系／體型 | 造型守則（一句） | ref 檔 |
|---|---|---|---|
| 殘日 `canri` | 祖靈／elite×1 | **暗盤外要有一圈粗細不均的亮邊、亮點必須偏心**——暗盤加一顆正中的亮點是齒輪（`bow._traps_4A ①`），暗盤加一圈亮邊才是日；芒不得等分等長，等分放射就是輪子。 | `docs/experiments/2026-09-07-ref-canri.md` |
| 大士爺紙尊 `dashiye` | 香火／ward×1 | **「紙」只做得出三件幾何訊號：沿邊一列剪刀鋸齒、扁（正面寬 ≥ 側面寬 2 倍以上）、平塗色塊硬邊相鄰**——表面質感那條路已被 `wuying` 紙紮感 0/8 封死；頭頂的小龕**不得比臉大、不得用灰白**，否則會被讀成面罩。 | `docs/experiments/2026-09-07-ref-dashiye.md` |
| 有應公 `youyinggong` | 陰氣／haunt×2 | **洞就是臉**：正面一個深黑的方龕口取代五官，內裡近黑（近黑＝洞、亮＝器官，`bow._traps_3B ④`）；那一點刺眼的紅只准落在一個部位（紅布／朱瓦／燭火三選一）；腰以下 `ghost_*` 虛化。 | `docs/experiments/2026-09-07-ref-youyinggong.md` |

**本卷量到的兩條通則（對 27 隻也成立）**：
1. **「上寬下窄 vs 下寬上窄」決定它是不是玩具**：殘日第 1 輪的軀幹往下漸寬（配重底），兩位讀者的主詞直接是「不倒翁／陀螺」；翻成上寬下窄之後玩具名詞歸零。**任何直立的東西，底比肩寬就會落進不倒翁語意場。**
2. **haunt 的虛化錐體在中性底棚拍上就是陀螺的輪廓**：有應公三輪六位裡有三位主詞是「陀螺」。腰以下收成一根尖的 `mist` 是 `redhat` 起的共用骨架，這條代價由六隻共同承擔——要拆得改體型語彙（散開的多股裾），不是改單隻。

**M-A1 現況（2026-09-07）**：三尊盲讀**三輪皆未過**，依凍結檔交最佳版標「未過」待使用者簽字，逐條在 `docs/experiments/2026-09-07-legend-art-evidence/blindread-v2.md`。

## 10. 招式視覺語彙（2026-09-11 使用者授權新增，v0.55「招式可辨性卷」；§0–§9 一字不動）

這一節管的是**招式特效**，不是生物（§0–§7）也不是場景燈光（§8）。它是 §1–§3 那四件事
（剪影／主色／材質／節奏）在特效層的延伸：**低多邊形沒有貼圖，剪影仍然是唯一剩下的辨識手段**（§7）。

**為什麼要有這一節**：2026-09-11 的 27 支招盲讀實測（兩位 context-free 讀者，
`docs/experiments/2026-09-11-fx-blindread-r{1,2,3}/`）——完整版就有 14 支兩位都認不出；
14／27 共用同一顆白光球、19／27 共用同一圈腳下光環、9／27 共用同一條白虛線。
特效語彙沒有權威落點，每一卷都會重新發明一次，這是分岔的成因。**單一事實來源＝`js/trait-fx/vocab.js`**，
本節是它的人類可讀版，兩邊由 `tests/fxvocab.test.mjs` 釘在一起。

| **主色** | `key #3f6fd8` 靛藍／`hot #ffd9a0` 土金／`line #7ea8ff`／`ink #0a1230` | `key #ffc21e` 鎏金／`hot #ff5a3c` 硃紅／`line #ffe08a`／`ink #2a1004` | `key #bdf0dc` 冷屍白青／`hot #ff2f3a` 那一點刺眼的紅／`line #6fae90` 苔綠／`ink #04120c` |

| **腳下語彙** | **垂直光柱** | **貼桌方陣**（圓環／光盤限縮到本系） | **不規則暗斑／水漬**（濕、無主、邊緣不規則） |
| **徽記材質** | `MAT_SOLID` 實心本體＋`MAT_LINE` 描邊；`MAT_GLOW` 只用在命中的爆點 | 同左 | 同左，另加 `ink` 外描邊（本體很亮，需要暗邊才切得出背景） |

**背景的兩個對手**（三系共通）：桌面 `TABLE_COLOR 0x6b3418`（`js/scene-env.js:8`）、
牌桌段夜空 `0x1e1a46` 與水平線 `0x4a2030`（`ENV.SKY_STOPS`，§8）。

### 10.2 徽記規則（一招一枚法寶剪影）

1. **一招一 kind、一 kind 一招**（雙射）：27 支招各自唯一，對照表在 `js/trait-fx/vocab.js` 的 `EMBLEM_OF`。
   三尊（`canri`／`dashiye`／`youyinggong`）另有三個 kind，走同一份表。
2. **是剪影不是模型**：27 隻裡有一半的法寶根本不在 GLB 裡（`xianji` 只有一隻鹿沒有刀、
   `tiger_c` 沒有「印」、`hairpin` 沒有「簪」骨）——剪影是低多邊形唯一剩下的辨識手段（§7）。
3. **複雜度上限**：每個 kind ≤ 24 個外框頂點（三角化後 ≤ 22 個三角形）。
   同一 kind 的 geometry **建一次全場共用**；同一招要 ≥3 份時走 `InstancedMesh`（一個 draw call）。
4. **出招瞬間必須有新增元素**：第一格畫面上就要多出常駐造型上沒有的東西。
   法寶本身是常駐造型（旗、燈、符）時，**常駐的那一份不算數**——要有一枚放大的徽記亮相。
5. **非加色**：徽記本體一律走 `MAT_SOLID`（`NormalBlending`）。
   加色混合的東西一旦越過 bloom 門檻就往白色去，**系色在畫面上活不下來**——
   這是「顏色分不出、全是白」的機制成因。解法是換材質與換形狀，**不是調 bloom 或 `EXPOSURE`**（§8 明寫）。

### 10.3 因果三段

每一招都要能讀出「誰出招 → 什麼飛過去 → 誰被打到」：

| 段 | 內容 | 能不能省 |
|---|---|---|
| **windup** 出招方動作 | 骨骼前搖一格到位＋徽記在手上／身上亮相 | 不能省——這是「誰在出招」的唯一來源 |
| **travel** 飛行物／連線 | 徽記本體飛出去或掃過去，拖尾跟著 | 不能省——這是「哪一招」的唯一載體 |
| **react** 受招方反應 | 退縮＋命中火星＋在目標身上蓋印記 | 不能省——沒有它就沒有因果。增益招量在**受益方**身上 |
| settle 收勢 | 回彈 | **唯一可以省的一段**（短版壓到 20ms） |

**判準（防「喊了就算」）**：`windup` 要出招方有骨骼 `rot`／`shift` 絕對值 ≥0.08 或 `move`／`scale` delta ≥0.04
（只有邊光變化不算）；`travel` 要有一個 spawn 物位移 ≥ 出招方到目標距離的 40%（原地脹大的環、罩、光球不算）；
`react` 要受招／受益方有 `flinch`／`scale`／`move` delta ≥0.03（只有邊光或火星不算）。

### 10.4 色對比門檻與量法

**不用色票算 ΔE**——加色混合＋bloom 之後畫面上的顏色不等於色票值，那是重建的模型不是真實路徑。
一律用**凍幀 A/B 差圖**：

1. 在有桌面與夜空的真實場景演該招，於 travel 中點凍住時間軸；
2. 截圖 A（徽記／拖尾／印記 `visible=true`）；**只把這些 mesh 切 `visible=false`、其餘一切不動**，同一格再截圖 B；
3. `|ΔLuma| ≥ 6` 的像素即「特效像素」；
4. 判定：**特效像素數 ≥ 全畫面 0.8%**（活性）**且**這些像素「A 對同座標 B」的 **CIE76 ΔE 中位數 ≥ 28**。

兩幀之間只准有 `visible` 一個變數。只取最亮那幾顆像素、或整個畫面提亮，都會讓這個門檻假綠。

### 10.5 退役／限縮清單

| 語彙 | 處置 | 理由（盲讀原話） |
|---|---|---|
| 貼桌 `ring`／`disc` 光環 | **限縮為香火系專用**（＝儀仗的「陣」） | 兩位讀者獨立指出「只用腳下光環的招太多互相分不出」 |
| `dome` 半圓護罩 | **祖靈系退役**；香火換方框帆罩 | 讀者 A 直接把巴冷公主珠鍊的罩讀成山神庇佑 |
| 白色 `orb` 光球 | **只留射日神弓**（那是太陽） | 雷女之火被讀成射日、山神庇佑被讀成千里眼銅鈴 |
| 裸 `beam` 白色細線 | **降級成飛行物的拖尾**，不得單獨當主體 | 「看不清飛的是什麼東西」「一條白色虛線」 |
| 編舞裡的色碼字面值 | **全數移進 `vocab.js`** | 色票要有單一事實來源，否則下一卷又分岔 |

### 10.6 造型互撞不是特效層修得掉的

盲讀查到三組模型層互撞：拼板舟↔山豬牙飾、百步蛇紋盾↔拼板舟、虎爺印↔山豬牙飾。
本節的語彙只能**硬拉開**（各走各的徽記）；拉不開的列名交裁，**不得在演出卷裡改 GLB 或重出模型**。
