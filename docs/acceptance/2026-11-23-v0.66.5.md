# 驗收條件：v0.66.5 關掉只能看的視窗後，其他位置馬上可以點（2026-11-23，動手前凍結）

**要解決的事**（製作人 iPhone 試玩 v0.66.4 第 3 項；DECISIONS 2026-11-23「v0.66.5 放寬連點守衛…（製作人選甲）」）：
- 製作人原話：「有時候按他會等一下才出現」，補充「開局按 然後後續想按第二次按不出來 要等一下或是卡住的感覺」「大概1秒」「按了沒反應 再按第二次」。
- 原因（桌機量測，`tmp/v0664r/bagtap2.log`）：點座位看完袋子、按「關閉」或點背景，之後 150／300／450ms 點另一席都被吞，600／800ms 才開；c2f8abfc 與 v0.66.4 逐格相同，是既有行為。吞掉它的是相位閘（v0.53.4，`docs/experiments/2026-09-11-acceptance-phase-gate.md`）：關閉那一下讓手指底下換了東西，整個畫面吸收 `MAIN_GUARD_MS`＝500ms。
- 製作人選的方案（甲）：只放寬「關掉只能看的視窗」這一種——別人的袋子、角色卡、規則頁；自己的袋子有「送神回天」鈕，驗收時逐一確認。關掉後只擋關閉那一點附近，其他位置馬上可點；連按「關閉」兩下，第二下照樣被擋。

**範圍**：`index.html` 的相位閘與托盤守衛各加一道「附近」判斷、五個視窗的標題加標記、版號；測試。引擎（結算、亂數、數值、AI）一行不動。2026-09-11 凍結的三個數字（`MAIN_GUARD_MS`＝500、探針連按間隔 120ms、C1 的 ≤1s）不動。
**GPT：略過**（不改變玩法語意的修復：只改防誤觸守衛涵蓋的範圍，不改規則、數值、流程與畫面），列入本階段略過清單交製作人過目。

## 作法
- 「只能看的視窗」＝五個：`showBag` 的三種內容（逐件開標中、別人的袋子、自己的袋子）、`showRoleInfo`（座位 ⓘ）、`openHelp`（規則頁）。這五個的 `<h2>` 加上 `data-viewonly`；其他視窗（請神選尊、供奉詢問…）不加。
- 相位閘量「按下這一刻」開著的視窗有沒有這個標記；這一下派送完視窗已經關了、手指底下的簽名也變了 ⇒ 只記下落點與時刻（`VIEW_GATE`），不武裝整層。
- 之後 500ms 內、離那個落點不到 `VIEW_GUARD_R`＝100 CSS px 的點擊照樣吞；托盤收的是 pointerdown、不經過 click 那一層，`trayTap` 另外呼叫同一支判斷。
- 不放寬的：視窗裡按了別的、視窗沒關（送神回天、切換效能資訊）；沒有座標的點擊（鍵盤 Enter／Space）；沒有標記的視窗。這三種照舊整層吸收。
- 半徑 100px 的依據：Android 判定「同一處連點兩下」的距離上限（`ViewConfiguration` 的 `DOUBLE_TAP_SLOP`＝100dp）。實測（`tmp/v0665/geom.log`，844×390、667×375、932×430，盯上頁與出價頁）：各視窗關閉鈕中心到任一席座位 ≥175px、到主鈕 ≥216px；別人袋子的關閉鈕底下在三個尺寸都壓著托盤 1 號格（盯上頁點到就是公開盯上），所以「附近」那一塊一定要擋。
- 已知取捨：視窗開著時底下若自己換了東西（例如開標演出還在跑），關掉後點別處不會再被這道閘吸收；和沒開視窗時看著畫面變化是同一種處境，這道閘本來也只管「點擊同步造成的切換」。
